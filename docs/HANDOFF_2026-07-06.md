## 2. システム構成（3段パイプライン）
1. **①計算骨格生成**: `Blueprint`（問題の型）＋`Atom`（Noun=図形/数, Verb=操作、SymPyで計算）が `MiddleRepresentation`(MR) を作る。
2. **②LLM翻訳**: `LLMTranslator`（Gemini `gemini-flash-lite-latest`）が MR を自然言語の問題文・解説へ翻訳。
3. **③図レンダリング**: `visual_dsl` を SVG 化。
- `master_data/mapping.json`（184レッスン）が各レッスンに Blueprint・`difficulty_levels`・`required_tags` 等を紐付ける中心データ。
- エンドポイント: `/problems/inspect`（POST, **LLM翻訳前の生MRを返す＝LLMフリー**）、`/problems/generate`（①②③通した最終問題＝実LLM）。
- Python 実行は必ず `.venv/bin/python`（system python に sympy 無し）。テスト: `SKIP_LLM_IN_TESTS=true .venv/bin/pytest tests/ -q`。

## 3. 伸び悩みの診断（Opusによる設計レビュー）
**2つの構造問題**:
1. **計算骨格ファーストを全形式に強制**: SymPy数値骨格→LLM翻訳は `calculation` には最適（SymPyが正しさを保証＝moat）。
   だが `word_problem/proof/knowledge/visual` にも同型を強制し依存が逆。form/difficulty が「骨格への後付けスタイル指示」に堕し
   生成の構造を決めていなかった。
2. **評価ループの空回り**: 評価が `/inspect`(LLM前) かモックに対してで**偽陰性**。修正打点が症状レベル（Blueprintを11→17個と線形追加）。
   固定の参照正解セットが無く改善が測定不能だった。

**打ち手**: ①非計算形式は「骨格→翻訳」から「**生成してから検証(generate-then-verify)**」へ反転。
②評価を**実出力×決定論ゲート**に固定。オペランドジッターの難易度を構造ベースへ。

## 4. 中核戦略（ユーザー制約を満たす設計）
- **評価ループにLLMを使わない**（LLM-as-judge禁止）。理由: 生成AIと評価AIが同一だと循環／Geminiクォータ節約／決定論は再現可能・無料。
- **生成は稀・評価は毎回**の非対称: 実LLM出力(product)は1回だけ生成・凍結し、決定論ゲートは毎回それに対して走らせる。
- **evaluator = verifier**（設計の背骨）: フェーズ2で作る決定論ゲートを、フェーズ3で生成時の受理／棄却フィルタに昇格させる。評価作業を捨て駒にしない。
- SymPyが計算した数値・答えは**絶対に変更しない**（moat）。
- **症状ごとのBlueprint追加で握り潰さない**。form/difficultyは構造で直す。

**2026-07-06 追記（実装時の発見）**: g2_l22/g2_l23/g2_l30 は当初案の `force_proportion`（Lv1=true/Lv2=false）
では直せなかった。理由: 3件とも `execute_blueprint=FunctionGeometryFusionStructure` で、`TriangleAreaVerb` が
「2直線が両方とも原点を通る（切片=0）と三角形の面積=0で検証失敗」というガードを持つ。mapping の `atom_constraints`
は Atom 型ごとに1つしか指定できず func_a/func_b 両スロットに同一設定が適用されるため、`force_proportion:true` を
両方に適用すると100%生成失敗（CleanSolutionExhaustedError）になることが判明。代わりに実装済みの
`LinearFuncAtom.max_intercept`（Lv1=小さい切片/Lv2=大きい切片）で区別し、G6-b PASS・G6-a悪化なしを確認した。
force_proportion は「Blueprintの構造（三角形面積前提）と非互換」というBlueprint文脈依存の制約がある点を
今後の参考として記録する。

**完了条件**: 8件（混在2件は(a)部分）が G6-b PASS。`pytest` 全通過。論理単位でコミット（末尾に下記フッター）。push しない。

## 10. 原則・落とし穴（厳守）
- 評価ループにLLMを入れない。ground truth とゲートは常にLLMフリー。product は稀に生成・凍結。
- SymPyの答えは不変（moat）。ゲートは検査するが変更しない。
- ゲートは純関数＋データ外出し。個別レッスンをハードコードで握り潰さない。精度優先（**偽FAILを出さない**、取りこぼしは他ゲートで補う）。
- 症状ごとのBlueprint追加をしない。form/difficultyは構造で直す。
- **サブタスクごとに逐次コミット**（レート制限で中断しても失わない）。push はユーザーが明示依頼するまでしない。
- コミットメッセージ末尾に必ず:
```

Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>
```
- 「自然さ（市販レベル）」は決定論ゲートで証明しきれない。マイルストーンごとの人手/LLMスポットチェックは**ループ外**で（毎回は回さない）。
