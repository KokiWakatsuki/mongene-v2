## 2. 6つ目のゲート `answer_size`（D-32）

### 何を測るか

**問題文の数ではなく、答えの形。** 標本調査の「20000個」・有効数字の「9780」は
大きくて正しい。壊れているのは、生徒がノートに書き写す**答え**のほうだった。

| 測るもの | 既定の上限 | なぜ |
|---|---|---|
| 分母 | 12 | 約分後の分母。大きいと筆算で扱えない |
| 分子 | 100 | 仮分数の分子 |
| 根号の中 | 60 | 平方因数を外に出しきったあとの数 |

**整数そのものの大きさは測らない**（測ると単元ごとの宣言だらけになって歯止めの
意味が消える）。

### 置き場所

```
engine/core/verify/answer_size.py   測り方の単一の真実（recipe と eval が同じ関数を通る）
engine/eval/answer_size.py          歯止め（6つ目のゲート。__main__ に組み込み済み）
SpecLevel.answer_size_max / _reason 宣言（理由が無いとロードで落ちる。dup_rate_max と同じ形）
```

**別々に持ってはいけない。** 生成側が通す形と検査側が落とす形がずれると、
通らない seed が出続けるか、逆に検査が空振りする。

### 初回の実測で 56 セルが上限超えだった

| 型 | 件数 | 直し方 |
|---|---|---|
| 量を仮分数で書いていた | 6 | 表示の作法（`fmt_measure`）。**値は変えない** |
| 根号の中が開けない大きさ | 17 | 答えの大きさで測って**引き直す**（定義域はそのまま） |
| 分母・分子が教材の大きさを超える | 8 | 同じ |
| 構造的に大きいのが正しい | 25 | **理由つきで宣言** |

## 3. 次の人がいちばん知るべきこと

### ★ 引き直し（redraw）は dup を悪くしない。ただし累乗は例外

根号の中は**辺を小さくしても下がらない**（7,12,13 の直方体は √362、3,4,12 なら
√169=13 で根号が消える）。だから上限は「辺の大きさ」ではなく「**開ける形か**」を
選ぶ＝**定義域を狭めない**。実測でも三平方10セルは rejects 0/120・dup ≤ 0.13。

**例外は累乗だけだった。** 累乗は底の分母をそのまま2乗・3乗するので、既定の分母12では
`(3/4)² = 9/16` すら落ちて分数の底が1つも使えず、dup が 0.37/0.42 に跳ねた。

1. 上限を 216（=6³）に宣言 → 0.16/0.25
2. Lv2 だけ残ったので**道具を1つ増やした**（小数の底。Lv1 は前から持っていた）→ 0.17

**単元の計算の型が答えの大きさを決めているときは、上限のほうを宣言する。**

### ★ 同じ量が、セルによって小数と仮分数で書かれていた

箱ひげ図のセルは `13.5`、四分位数のセルは `27/2`。`_fmt_half` は**あったのに
3つの solver がそれを通していなかった**。面積・体積・長さにも同じ食い違いがあった
（`225/2 cm³`・`333/2`・`2065/2`）。

**量には小数、式の中の数には分数**（`x = -107/12` は分数のままが正しい）。
`fmt_measure`（`engine/packs/math/solvers/arithmetic.py`）に集約した。
**割り切れない値は分数のまま出す**——量として書けない形を隠さないため。

### ★ 走査が空でも読むと出る、は6回目も健在（D-33）

機械の走査（`scan_defects` / `scan_explanations`）が全部0件のあとに、解説の日本語を
読んで**問いと答えの食い違い**が出た（`g1_l34.knowledge.Lv1`）。

```
問題文: 「次の文の正誤を答えよ。『a>0のとき、双曲線は第1象限と第3象限にある。』」
答え  : 「右上と左下の部分にある（二つの枝からなり、x軸・y軸と交わらない）」
```

**正誤を問うているのに答えが場所の記述。** 加えて「象限」は中学の教科書に無い用語
（高校で扱う）で、比例定数が `263`（`a_domain: [-500, 500]`）だった。
**答えは符号だけで決まるので、値を広げても問題の中身は1つも増えていない**
——広げていたのは dup_rate を通すためだけだった。

読み方: `scratchpad/dump_explanation_texts.py` が**数と記号を伏せて文型ごとに束ねる**
（4,169手 → 1,131文型）。文型を読み切れば日本語は読み切ったことになる。
