## 2. 7つ目のゲート `statement_size`（D-34）

`answer_size`（6つ目）は**答え**を測る。これは通ってしまう:

```
1辺の長さが445cmの正三角形ABCで、辺BCの長さと∠Aの大きさを求めよ  → 445cm と 60°
```

答えは正しく割り切れてもいる。**壊れているのは場面のほう**（4.45mの正三角形は作図もできない）。

- 上限は**単位ごと**（cm 100・m 3000・° 5040・人 100000 ほか）。**裸の数は測らない**
- 直し方は **`pipeline` が問題文を測って組み直す**（`_construct_with_statement_size`）。
  問題文はどの recipe も `mr.given` に置くので、**1か所**で12セルが直った
- 記録・母集団・測定値など**大きいのが正しい**19セルは YAML に宣言

### ★ ここで踏んだ最大の罠: **harness が pipeline の写しを持っていた**

`engine/eval/_harness.py` に `_construct_with_bounded_retry` の**独自の写し**があり、
`dup_rate` / `level_sep` / `retry_stats` / `check_cell` は**そちらを通っていた**。
そのため組み直しを pipeline に足しても、**ゲートは生徒に出るのと違う MR を測っていた**。

気づかずに「dup は動いていない」と報告しかけた。写しを消して pipeline と同じ経路に
してから測り直したら、**4セルが dup 0.20 超**（0.25〜0.42）だった——組み直しは
「通る組」に抽選を寄せるので、**dup は必ず上がる**。数を現実に戻した結果なので、
理由つきで `dup_rate_max` を宣言した。

**教訓: 「測る側が本物と同じ経路を通っているか」を先に確かめる。**
写しがあると、ゲートは静かに嘘をつく。

## 3. 解説の中間値（面③）— **安全だと分かったが未実施**

5回目の引き継ぎ書は「途中の手に値を書くとヒントに載って答えの先出しになる」と
書いていた。**これは narration についてのみ正しい。**

```python
# engine/core/render/t1_template.py _build_hints
return [step.narration for step in sq.steps[:-1]]      # ← narration だけ
```

**ヒントは `result_display`（解説の括弧の中）を見ない。** だから
**括弧に中間値を書いても漏洩しない**。いま括弧が指示の言い直しになっている手が
**817手 / 325セル**ある（`scan_explanations` の「解説の括弧が指示の言い直し」）。

やるなら: 各 solver の `Step(result_display=...)` に、その手で得た値を入れる。
27 solver 分の機械的作業で、**golden が大量に動く**（値が増えるので）。
`narration` は触らない（触ると漏洩する）。

## 4. prerequisites / error_causes（面⑤）— **配線は動く。中身が無い**

要件定義（`docs/requirements_2026-07-11.html` §3②）では、**知識グラフ（前提関係DAG）と
誤答要因の語彙は「教育者（高橋）が編集できる形式」の共有データ資産**であり、
エンジンの担当は「**要因 → 戻り先座標を解決して問題を供給**」（F-7）のほう。

実測（`scratchpad/audit_progress.py` に出力を足した）:

```
概念                 577
前提関係の辺          2     ← UC-2 の「前提単元へ戻る」が動かない
誤答要因              3     ← 原因の選択肢が出せない
要因タグ付きのセル      5 / 630
```

**エンジン側は動く。** 3つの要因すべてで「要因 → 戻り先座標 → その座標の問題を供給」が
通ることを実測した（`remedial_cases` + `generate`）。

つまりこれは**エンジンの欠陥ではなく、共有データ資産の未入力**。次にやるなら、
エンジン側の仕事ではなく**教育者と一緒に語彙を作る**仕事になる。
穴が見えないのが一番まずいので、監査に充足率を出すようにした（台帳は 630/630 で
埋まって見えるため）。

## 5. 逆翻訳ゲート G-BT（面⑥）— 最大の穴を実測で塞いだ

`docs/llm_template_expansion.md` §2 の穴。double-solve は recipe と同じ立式関数を
呼び直しているので、**日本語が本当にその数式を意味しているか**は誰も見ていなかった。

```
scratchpad/bt_dump.py     問題文だけを書き出す（答え・式・recipe は見せない）
scratchpad/bt/answers.tsv 読み手が日本語だけから解いた答え
scratchpad/bt_check.py    エンジンの答えと値で突き合わせる（表記差を吸収）
```

| 対象 | 結果 |
|---|---|
| 全 word_problem セル 94問 | **意味の食い違い0**（出た9件は全部表記差） |
| 値で文が反転しうるセル 36問 | **0**（長い/短い・増え/減り・余り/足りない・反対向き/同じ向き・2回目に出会う） |

**この検査は自動では回せない**（独立した読み手が要る）。回帰の歯止めではなく、
**文型を足したときに1回通す関門**として使う。今回の 130問は
「文型ごとに数 seed を見た」であって**全 seed の保証ではない**。
