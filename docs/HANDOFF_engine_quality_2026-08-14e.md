## 2. 面① 図が教材として読めるか

### 2.1 作った道具

`scratchpad/scan_figure_legibility.py`（新規）。SVG の `<text>` と線分を座標で
拾って、次を数える:

| 見出し | 何を見るか |
|---|---|
| ラベルが重なる | 文字の箱どうしが 15% 以上重なる |
| 枠からはみ出す | 文字の箱が viewBox の外 |
| 線がラベルを貫く | 線分が文字の箱を**貫通**する（端が箱の中で終わるのは指示なので許す） |
| 文字が小さい | font-size < 9 |
| 問題文の点が図に無い / 図の点が問題文に無い | 点名の対応 |

1. **属性名の数字**。`([a-zA-Z-]+)=` で属性を取っていたので `x1`/`y1` が

   0件が出たら、まず検査が動いているかを合成 SVG で確かめる。
2. **白フチは2枚の `<text>`**。下敷きを数えると「ラベルが重なる」が全件で立つ。
3. **「求めよ」の対象は図に無くて当たり前**。作図の点 P、移動後の A'B'C'、
   回転の中心 Q。24件の指摘は全部これだった。
4. **点の名前は読点で並ぶ**（「2点M、Nと直線ℓ」）。先頭だけ採ると残りが
   「図にしか無い名前」に見える。
5. **「線が枠の外へ出る」は測れない**。座標平面のグラフは枠の外まで引いて

## 3. 面② 全 seed での日本語と数式の対応（G-BT）

### 3.1 何が足りていなかったか

7回目に読んだのは 130問＝「セルごとに数 seed」。**文型がいくつあるか**を

### 3.2 作った道具

`scratchpad/bt_patterns.py`（新規）。問題文から

  ・params の文字列の値（品物・人名・場面。**入れ子の dict も辿る**） → `＠`

`scratchpad/bt/problems3.md` に書き出す。

**伏せ方を間違えると文型が爆発する。** 最初は params の文字列だけを浅く
伏せていて 1,029 種（`exam_l1` の1セルだけで 24 種＝点名 J/L/M… の違い）。
点名と変数文字と入れ子の params を伏せて（§6 の数）まで落ちた。

### 3.3 読み方

## 4. 面③ 解説の日本語そのもの

### 4.1 測り方

`scratchpad/dump_explanation_texts.py` で文型を出して**全部読む**（1,121種）。
機械の検査は面③（8回目）で尽きているので、ここは通読しかない。

「理由を表す語があるか」は指標にならない（「かきの個数を x とおく」に理由は
要らない）。読んで判断する。

### 4.2 直したもの

**証明の解説が、どの行も「次がいえる。」で締まっていた。** 解説の接続詞は
「次に、」が自動で付くので、

```
次に、対頂角は等しいことから、次がいえる。（∠AOB ＝ ∠COD）
次に、2組の辺とその間の角がそれぞれ等しいことから、次がいえる。（△ABO ≡ △DCO）
次に、合同な図形では対応する辺（角）はそれぞれ等しいことから、次がいえる。（∠ABO ＝ ∠DCO）
最後に、錯角が等しいことから、次がいえる。（AB ∥ CD）
```

が4行続き、**何が分かったのかは括弧を読むまで分からない**。主張の形
（`≡`/`∽`/`∥`/`⊥`/`：`/`°`/`∠`/`＝`）から「何が分かるか」を決めるようにした
（`recipes/geometry_proof.py::_claim_tail`）:

```
次に、対頂角は等しいことから、等しい角が分かる。（∠AOB ＝ ∠COD）
次に、2組の辺とその間の角がそれぞれ等しいことから、2つの三角形が合同だと分かる。（△ABO ≡ △DCO）
最後に、錯角が等しいことから、2直線が平行だと分かる。（AB ∥ CD）
```

**それ以外の解説の日本語は直すところが無かった。** 長い手はどれも
「〜だから」「〜ので」「〜ことから」で理由を述べており、短い手（「次に、
左辺を因数分解する」）は理由の要らない手続きだった。

### ★ここで踏んだ、次の人が必ず踏む罠を3つ

**1. `pytest engine_tests` は `--no-cov -n 4 --dist worksteal` を必ず付ける。**
`pyproject.toml` の `addopts` は**別プロジェクト（`apps/`・`tests/`）向け**で、
`--cov=apps` は engine を1行も測らないのに計測の重さだけ乗る（**実測 2.6倍**）。
さらに `--cov-fail-under=80` のせいで**全部通っても終了コードは 1** になる
（`Total coverage: 0.00%` で必ず落ちる）。終了コードだけを見る自動判定は書けない。
`--dist worksteal` が要るのは、既定の `load` だと `eval/test_eval_suite.py` の
重い群が1本のワーカーに固まり、**残り3本が遊んだまま終盤で1時間止まる**から。
直列だと1時間37分たっても 0%（件数の大半を占める `unit/` に入れない）。

**2. golden は正真正銘の関門。** `engine_tests/golden/test_golden_slice.py::test_golden_regression`
が、承認した Problem 全文と再生成を突き合わせている。
9回目に「golden を読むテストは無い」と誤判定して承認を途中で止め、
**失敗7件のうち6件をそれで作った**（`engine_tests/golden/` を `ls` して
`math.*` ディレクトリだけ見て、同じ階層の `.py` を見落とした）。

**3. 失敗数は進捗行の `F` で数える。** `grep FAILED` は**実行が全部終わってから出る
まとめ行**しか拾わないので、途中で使うと必ず「0件」と出る。9回目に一度誤報告した。

```bash
sed -n '/workers \[/,$p' <log> | grep -o "^[.FEsx]*" | tr -cd 'F' | wc -c
```
