## 進め方の運用ルール（踏んだ事故の再発防止）

1. **worktree の基点確認を必ず最初にやらせる**
   （過去に旧 master 基点で作られる事故が複数回。ずれていたら `merge --ff-only` で揃える）
2. **`spec_cli check` の `dup_rate` は常に 0.0 で当てにならない**
   → `scratchpad/check_cell.py` の 100seed 実測が本物
3. **ゲートは答えが 0 や 1 に潰れる退化を素通りする**
   → property テストで固定する
4. **eval は「テスト緑」とは別に必ず回す**
   （fingerprint が op 列なので Lv 間で op 列が同じだと level_sep が黙って壊れる）
5. **check_cell が ALL_OK でも pytest 全走は別に必要**（2026-08-07 に2件踏んだ）
   - `frames.py` の `asked_vocab` を増やしたら `test_frames.py` の台帳 frozenset にも足す
   - word_problem は `params["numbers"]` 必須・値はすべて本文に現れること
     （図が数を与えるセルは `"numbers": {}` と明示。空なら本文に算用数字が無いことを
     併せて検査する）
6. **level_sep は「何を文字に置くか」を動かすのが一番効く**
7. **params は「本文に出ている数値」だけ**（導出値を置くと検証に穴があく）
8. **並列度は3〜4体**。競合面は `concepts.yaml` と各 `__init__.py` のみ（追記）なので
   順次マージすれば衝突は軽微。**ただし `test_recipes.py` は両側が末尾に追記するため
   必ず衝突する**。`git show :2:<path>` / `:3:<path>` を取り出し、
   ours + theirs の追記ぶんを末尾に連結して解決する（素朴な手作業は他方のブロックを
   別のテスト関数の中に差し込む事故になる）
9. **サブエージェントは利用上限で落ちうる**。成果物は worktree に残るので、
   次のセッションが `git -C .claude/worktrees/agent-* status` で拾って検証・マージする。
   **落ちた体は DoD の途中で止まっている前提で、check_cell から全部やり直す。**
10. engine 検証は `--no-cov` 必須。フルスイートは約28-33分（47,621テスト）
