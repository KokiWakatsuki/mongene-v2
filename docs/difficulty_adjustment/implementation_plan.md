# 難易度設定の抜本的見直し（Difficulty Adjustment）

ユーザーからの素晴らしい提案に基づき、1〜100のスケールに直接マッピングするのではなく、**様々な要因（大単元、小単元、問題形式、図の有無、小問構成など）を「Raw Score（生の難易度ポイント）」として独立して評価し、その合計値を1〜100に正規化するアプローチ**を採用します。

これにより、各要素の難しさを妥協なく厳密に数値化でき、入試問題のような超難問から1+1レベルの基礎問題までを正確なスケールで表現できます。

## 1. 難易度の新しい評価軸（Raw Score モデル）

### Raw Score の算出要因

**① 大単元（Large Unit）: 100 〜 900 ポイント**
（Web調査の「つまずきやすさ」を反映）
*   中1「正の数・負の数」: 100
*   中1「一次方程式」: 250
*   中2「1次関数」: 550
*   中2「平行と合同」: 500
*   中3「相似な図形」: 800
*   中3「三平方の定理」: 900

**② 小単元（Lessonの性質）: 0 〜 400 ポイント**
*   基礎・意味・導入: +0
*   計算・解き方: +50
*   性質・定理: +100
*   利用・文章題: +250
*   融合・発展・最短距離など: +400

**③ 問題形式（Problem Form）: 0 〜 800 ポイント**
*   `calculation`（計算）: +0
*   `word_problem`（文章題）: +400
*   `proof`（証明）: +800

**④ 図の有無（Visual / Hint）: -100 〜 +300 ポイント**
*   図形問題で図が親切に与えられている: -100
*   図形問題で図がなく、自分で描く必要がある: +300

**⑤ 計算の複雑さ・手数（Steps & Digits）: 0 〜 800 ポイント**
*   手数の深さ（`step_depth`）: 1ステップにつき +100（最大 +500）
*   桁数や数値の複雑さ（`digit_penalty`）: 1段階につき +100（最大 +300）

**⑥ 構成の複雑さ（Unit Mix & Subquestions）: 0 〜 1100 ポイント**
*   複合単元化（`unit_mix_bonus`）: +500
*   入試レベルの積み上げ小問構成（`incremental`）: +600

### 正規化（Normalization）
*   **理論上の最小値 (RAW_MIN)**: 100（中1正負の数、導入、計算、ペナルティなし）
*   **理論上の最大値 (RAW_MAX)**: 4300（三平方の定理、発展、証明、図なし、フルステップ・フル桁数、複合・入試構成）

Raw Score を算出した後、以下の式で 1〜100 に正規化します。
`Difficulty (1-100) = 1 + 99 * (Raw Score - RAW_MIN) / (RAW_MAX - RAW_MIN)`

## User Review Required

> [!IMPORTANT]
> **「要因ごとに固有のポイントを足し合わせ、最終的に1〜100に正規化する」**というこの Raw Score 手法は、まさに数学的で厳密なアプローチです。
> 大単元ごとのポイントも、最も易しいものを100、最も難しいものを900とすることで解像度を上げています。
> この評価指標（配点バランス）について、違和感や修正したい点はありますでしょうか？

## Proposed Changes

### 1. `base_difficulty.py` の再設計
*   `GRADE_BASE`, `DOMAIN_BONUS` を完全に削除。
*   `LARGE_UNIT_RAW_SCORE`（100〜900）と `LESSON_RAW_SCORE`（キーワードベースで0〜400）を定義。
*   関数 `compute_raw_y_base(large_unit, title)` を作成し、小単元自身のベースとなる Raw Score を返します。

### 2. `difficulty_reconciler.py` の抜本的改修
*   正規化定数 `RAW_MIN = 100`, `RAW_MAX = 4300` を定義。
*   ユーザーが指定した `target (1-100)` を `raw_target (100-4300)` に逆算（デコード）します。
*   `raw_y_base` と `raw_target` の差分（`raw_delta`）を算出し、その差分を埋めるように `problem_form` (+0〜+800)、`hint_reduction` (+300)、`step_depth` (+100単位)、`subquestion_strategy` (+600) などのパラメータに分配・決定するロジックに変更します。

### 3. マスターデータ (`mapping_seed.json`, `mapping.json`) の更新
*   JSONには 1〜100 に正規化された `y_base` ではなく、調整前の基準点となる `raw_y_base` を記録するか、もしくはベース単元の正規化難易度（形式を含まない）を記録するようスクリプトを改修します。

## Verification Plan
1.  新しい Raw Score モデルに基づき `mapping.json` を再生成。
2.  `test_difficulty.py` を完全に書き換え、`target=1` の時にペナルティが0になること、`target=100` の時に全ての難化フラグが立つことを確認。
3.  実際にシステムに組み込み、生成される問題難易度がユーザーの直感（1=1+1, 100=入試難問）と一致するか目視検証。
