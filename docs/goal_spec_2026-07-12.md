## 1. 入力を考える — 「単元 × 難易度 × 問題形式」で良いのか

### 1.1 入力が満たすべき性質（システムの目的からの導出）

エンジンはシステム概要図の学習ループ（要件 §2 UC-1〜UC-8）に仕える。ループが入力に要求する性質:

| ループ側の要求 | 入力への含意 |
|---|---|
| ロードマップは教科書目次で並べ替える（UC-6） | **単元**は授業1コマ相当の独立部品として指せること |
| ステージ進行は「同じ単元で段階を上げる」（UC-1） | **難易度**は単元内の段として指せること |
| インプット確認・計算練習・文章題・証明は別の学習活動（UC-1/2） | **形式**を指せること（採点の答え型・検証水準も形式で決まる） |
| 誤答→原因→戻り先（UC-2） | purpose=remedial と cause_id（入力済み） |
| 類題3モード（UC-4） | purpose=variant と variant_of（入力済み） |
| BKT は概念単位で習得度を追う（UC-7） | 概念は**入力の主キーではなく**、出力の concept_tags と options.target_concepts（絞り込み）で足りる |
| 再現・監査（F-2/F-17） | seed |

→ 要求されるのはまさに `generate(subject, unit, form, level, purpose, seed, options)`（要件 §4.1）であり、**現行契約はループの語彙と1対1で対応する**。

### 1.2 検討した代替案と棄却理由

| 代替案 | 内容 | 棄却理由 |
|---|---|---|
| A. 概念主キー | 入力を concept_id（知識グラフのノード）にする | 概念は問題より細かいタグであり授業・宿題の発注単位でない。教科書目次並べ替え（UC-6）と乖離。著作単位（1セル=1スペック、H2/H6）が組めず品質の機械判定が崩れる。概念絞り込みは options.target_concepts で既に可能 |
| B. 問題型ID | 「2点から式を求める」等の型IDを直接指す | 型は座標の**内部実体**（family/signature）として既に存在する。型IDを公開キーにすると「同じ単元で1段上げる」「単元の form 一覧」が表現できずホストが困る |
| C. パラメトリック入力 | 「分数係数あり・小問2つ」等の生成パラメータを入力に | 制約の語彙が発散し品質保証（Q3 難易度・F-3 重複の操作的定義）が不能になる。この種の制約は G2 の「回答傾向→制約」であり、**将来 options に追加する拡張点**として要件が既に予約（§4.1） |
| D. 手本問題入力 | 外部の問題を渡して類題を作らせる | variant（F-4）は自エンジン生成物の problem_ref で対応済み。外部教材基準は問題バンク（F-21・M3）の領域 |

### 1.3 入力に「入れない」と決めたもの（設計判断の記録）

- **誘導の有無（word_problem の Lv3=誘導あり / Lv4=誘導なし）**: 独立軸にせず**難易度の意味論に内包**する。誘導の有無は小問構成＝構造を変える（Q3「段＝構造差」と整合）ため。
- **題材・文脈（速さ／代金／食塩水…）**: 大きな題材差は**単元**が既に分離している（例: g2_l16 個数と代金／l17 速さ／l18 割合）。セル内の見かけの文脈差は variant B（context_slots）の領域。
- **小問数・問題規模**: family スペックが決める。複数問題の束は F-13 セット組成（M2）の仕事で、1問 API に混ぜない。

### 1.4 将来の変化への耐性

- **G2（概念情報生成）が来ても入力スキーマは変わらない**: G2 は「3つの概念情報 → G1 リクエスト列」への変換層として G1 の上に載る（要件 §3.1・D-8）。エンジンの公開契約が安定していることが G2 の前提。
- 変化はすべて **options の追加**（後方互換）と **セルの追加**（データ）で吸収する（F-19/F-20 Open-Closed）。

> **§1 の結論**: 入力は現行の 座標（subject, unit, form, level）＋ purpose ＋ seed ＋ options を維持する。

## 2. 入力の組み合わせを考える — 有効な組み合わせの設計

入力スキーマが決まっても「どの (単元, 形式, 難易度) が実在するか」は別の設計である。**掛け算（184×7×4=5152）は成立しない**——実在するのは疎な部分集合であり、その列挙こそが生成対象の定義（＝取りこぼしの正）になる。

### 2.1 組み合わせの設計規則（R-IN1〜R-IN6）

| # | 規則 | 内容 |
|---|---|---|
| **R-IN1 単元粒度** | 単元＝授業1コマで教える1つの考え方（教科書の節相当）。1学年 ≈ 60 単元。章単位は粗すぎ（難易度と形式が混ざる）、概念単位は細かすぎ（著作が破綻）。教科書目次との対応が取れること（UC-6） |
| **R-IN2 形式語彙** | 形式は「答えの型と検証水準が異なる出題様式」で分類する（7型: knowledge/calculation/find_value/graph_table/word_problem/proof/construction）。各形式は Answer 型（Choice/Symbolic/Graph）と検証水準（V1/V2/V3）に対応する——これが機械品質保証の土台（実装設計 §6.2/§6.3） |
| **R-IN3 難易度の意味論** | 段＝**構造の差**（解法 op 列・問い・小問構成が変わる）であり数値の大小ではない（Q3・過去最大の失敗 P-1 の再発防止）。**構造的に別の段が実在する場合にのみレベルを定義**し、4段への水増しをしない |
| **R-IN4 疎性の明示** | 全単元が全形式を持つ必要はない（証明は図形系のみ、作図は中1図形のみ等）。有効セルの正は capabilities API が返す（F-6）。無効な組は Unsupported で明示拒否（F-5） |
| **R-IN5 融合問題の疑似単元化** | 単元横断の入試融合問題（一次関数×図形、放物線×直線等）は**独立した疑似単元**（exam_l1〜）として座標化する。座標系の外に「特別扱い」を作らない |
| **R-IN6 変更管理** | 組み合わせの追加・分割・移動はデータ（input_spec → units.generated.yaml）の変更のみで行う（F-20）。ゴールの分母は常に最新の units.generated.yaml に自動追従する |

### 2.2 現行 input_spec_2026-07-08.json の適合状況（実測）

現行の列挙は上記規則に適合している:

- **総セル数 630**（naive 積 5152 の 12%）。学年別: g1=209 / g2=197 / g3=189 / exam=35（R-IN1: 184 単元、1学年 57〜60）。
- **形式別**: calculation 144 / knowledge 145 / find_value 105 / word_problem 100 / graph_table 76 / proof 51 / construction 9（R-IN2: 7型すべて使用。proof は図形系、construction は g1 図形のみ＝R-IN4 の疎性）。
- **7形式すべて持つ単元は 0**。形式数分布: 1形式=43単元 / 2=93 / 3=46 / 4=2（R-IN4）。
- **難易度**: バンド絶対値 基礎1/標準2/応用3/発展4。使用分布 Lv1=224 / Lv2=234 / Lv3=130 / Lv4=42、(単元×形式) あたり 1〜3 段（R-IN3: 水増しなし）。形式ごとに特徴帯がある（knowledge は Lv1 中心・word_problem は Lv2〜4・find_value は Lv2-3 中心）＝形式と難易度が独立でない実データの証拠。
- **exam_l1〜l7**（R-IN5）: 一次関数×図形／放物線×直線／動点／三平方×空間／確率複合／相似×比／データ活用——公立入試の頻出融合を疑似単元化済み。
- 各セルは desc（構造定義）・example（例題）・market_ref（市販教材上の位置づけ）を持ち、スペックの source_desc へ転記される（spec_lint R8）——**セル定義と生成物を突合検収できる**形が既に整っている。

> **§2 の結論**: 現行の 630 セル列挙を初版の正として採用する。ただし「これで全部か」は次の §2.3 で検証し続ける。

### 2.3 完全性の検証 — 写像監査（mapping audit）

列挙は市販教材・教科書から人手で設計した**仮説**である。完全性は信じずに測る:

- **手順**: 外部ソース3種（①教科書章末問題 ②市販標準問題集 ③公立入試過去問直近3年）から学年ごとに無作為 50 問を抽出し、各問題が「どのセルの生成空間に入るか」を判定する。
- **合格基準**: 写像成功率 **≥ 95%**（学年×ソースごと）。
- **不合格分の扱い**: (a) 新セル追加 または (b) 既存セルの desc/domain 改訂 のバックログとして起票（R-IN6 によりデータ変更のみ・コア不変）。**分母が増えるのは取りこぼしの発見＝正しい動き**。
- **実施時期**: M1 末（知人塾対象学年）と M2 末（全学年＋入試）。判定は V3（LLM 補助）＋V4（人間）。

### 2.4 既知の論点（正直な記録）

1. 誘導有無をレベルに内包する設計（§1.3）は、同一レベル帯の他形式と難易度感覚がずれる可能性がある → 写像監査と preview 検収（Q4）で観測する。
2. 入試の都道府県別傾向の tail は exam 7 疑似単元では拾い切れない可能性 → 監査の不合格分をセル追加で吸収。模試一式の構成は F-13 セット組成（M2）の領域。
3. 小学算数（D-7）は範囲外のまま——阿武町実証（2027/04）までに判断（要件 §10 M3）。

## 3. ゴール — 完成の数値定義

### 3.1 定義式

```
G1-BASE-DONE ⇔ (a) green セル数 = 630/630（分母は units.generated.yaml に自動追従）
            ∧ (b) eval 一式 exit 0（capabilities 全セル走査・生成不能 0・ゲート素通り 0）
            ∧ (c) 写像監査 ≥95%（§2.3・入力の組み合わせ自体の妥当性）
```

現在地: **29/630（4.6%）**。全て g2 の連立・一次関数クラスタ。

### 3.2 green（セル1個の完成）の定義 — 全て機械判定・稼働済み

| # | 判定 | 数値基準 |
|---|---|---|
| 1 | schema / lint | spec_lint R1〜R8 エラー 0 |
| 2 | smoke | 全レベル × 20 seed × 全9ゲート（G-SIG/FP/Q1/Q2/Q7/Q5t/GND/STY/Q5v）失敗 0 |
| 3 | preview 検収 | 人間の承認記録（Q4/Q6 の V4）＝ approval.yaml |
| 4 | golden | seed 1〜3 の Problem 全文固定・回帰 0 |
| 5 | 重複率 | **dup_rate ≤ 0.20 @ 100 seed**（＝100 seed 中 相異 ≥80 問） |
| 6 | レベル分離 | 多レベル family で fp（steps op 列）相異 |
| 7 | リトライ | bounded_retry 発動率 ≤ 5% |

**「全パターン × 3問（重複削除）」案との関係**: 方向は正しく、基準 #5 が「相異 ≥80/100」としてそれを**約26倍の強さで包含**する。ただし「×3 生成できる」だけでは壊れた問題も数えてしまうため、#1〜#7（正しさ Q1・形式 Q2・非漏洩 Q5 等のゲート通過）を green の定義とする（F-14 generate-then-verify）。

### 3.5 進捗の測り方（常時・機械）

- **量**: `python -m engine.tools.goal_progress [--json]` — 分母=units.generated.yaml × 分子=capabilities() を §3.4 の分類で集計。**未分類セル検出時は exit 1**。
- **質**: `python -m engine.eval --seeds 5 --dup-seeds 100`（green の実体検証・exit code で CI 連携）。
- ダッシュボード HTML 化は M1（実装設計 §8.3）。

### 3.6 埋める順序（規律つき提案）

**規律**: (1) C グループ単位で着手し、そのグループの T1 セルを 100% にしてから次へ（「薄く広く」の宙ぶらりん禁止）。(2) T3 セルは I2/I3 完成後にクラスタへ戻って埋め、単元を真の 100% に。(3) 事業優先（知人塾テスト範囲＝D-4）が判明したら該当グループの前倒しのみ許す。

| P1 | C5残 → C2残（宙ぶらりん解消） | 68/630 |
| P2 | C1 → C3（純代数量産） | 205/630 |

P4・P7 の後に写像監査を実施し、分母の増分をバックログ化する。

### 3.7 変更管理
