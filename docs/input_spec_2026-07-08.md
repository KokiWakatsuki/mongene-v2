# 入力層 確定仕様（単元 × 問題形式 × 難易度）— 2026-07-08

mongene-v2 は「問題が確定していない問題集」＝生徒が **単元→形式→難易度** を選ぶと無限に問題が湧くシステム。
この文書はその**生徒操作メニュー**をゼロベースで確定したもの。既存 mapping.json の supported_forms は正しさの根拠にしていない。
学習指導要領（4領域・3観点）と教科書/問題集の標準的出題タイプ、および**生徒がその単元で何を練習したいか**から各セルを導いた。
フェーズ①（入力の確定）の成果物。フェーズ②（生成できない理由の診断）・③（修正）の基準。

## 1. 問題形式（form）= 5型（＝生徒が選ぶ『何を問うか』）

| 形式 | 生徒の意図 | 観点 | 自然な難易度帯 |
|---|---|---|---|
| 知識 | 用語・意味・性質を確認したい | 知識 | 基礎〜標準 |
| 計算 | 手を動かして解く・処理をこなしたい | 技能 | 基礎〜応用 |
| 視覚 | 図・グラフを読む/かく、作図したい | 技能＋思考 | 基礎〜応用 |
| 文章題 | 文章の場面を数学にして解きたい（活用） | 思考・判断・表現 | 標準〜発展 |
| 証明 | 筋道立てて説明・証明したい | 思考・判断・表現 | 標準〜発展 |

作図は視覚のサブ型、「説明せよ」型は証明に統合。

## 2. 難易度 = 4バンド（基礎F / 標準S / 応用A / 発展D）

各 (単元×形式) に band レンジを割り当て、その範囲が生徒の選べる難易度になる。**全形式が全バンドに届くわけではない（形式と難易度は非直交）**。生徒が「自信ない→低め」「自信ある→高め」を選ぶ軸。

## 3. 単元の監査結論

- 大単元・小単元は学習指導要領4領域＋標準教科書配当に一致し **妥当**。本体177レッスンは全て単元定義OK。
- **入試対策7件** = 複数単元を横断する融合問題。データ的には再掲だが、**生徒が「入試対策やりたい」と選ぶのは正当**なので、**融合セクションとして単元ツリーに残す**（難易度は発展Dまで）。

## 4. 現行からの変更サマリ

- form 集合が現行と変わるレッスン: **63/184**。
- 変更軸: (a) 意味導入回→知識主、証明・導出回→証明主に据え直し (b) 利用回→文章題主を明示 (c) 誤って付いた証明の削除（対頂角・多角形の内角/外角和） (d) 関数クラスタの題材純化（交点+面積は l27/l29/l30 のみ） (e) 基礎計算回は計算のみに整理。
