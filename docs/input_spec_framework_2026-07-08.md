# 入力層 確定仕様フレーム v2（7型タクソノミー）— 2026-07-08

mongene-v2 は「問題が確定していない問題集」＝生徒が **単元→問題形式→難易度** を選ぶと無限に問題が湧くシステム。
本フレームは生徒操作メニューの物差し。**既存 mapping.json / v1 spec の分類は根拠にしない**。

## v1 からの重大修正（ユーザー指摘）
v1 の「計算」は2つの別物を混ぜていた＝①純計算（式を処理）と②図形の計量（図から量を求める）。
実在の入試で空間図形・相似は全て「図と数値から長さ・体積を求める求値問題」であり「計算問題」ではない。
→ **判別基準を「与えられるもの・立式の有無・現実場面の有無」に固定**し、相互排他な**7型**に精緻化。

## 問題形式 = 7型（相互排他・判別基準つき）

| # | 形式 | 判別（与えられる → 作る／立式／場面） | 例 | 主な領域 |
|---|---|---|---|---|
| 1 | **知識** knowledge | 用語・意味・性質の問い → 語/記号/選択 | 「絶対値の意味」「合同条件を選べ」「比例定数とは」 | 全 |
| 2 | **計算** calculation | **式が与えられ**、立式せず処理・変形・求解 | 「√12を簡単に」「2x+3=7を解け」「展開せよ」「x=5のときy=?（代入）」 | 数と式／関数の代入・処理 |
| 3 | **求値問題** find_value | **図・点・条件**から**自分で関係を立式**して量/式を求める（場面は数学的・現実物語でない） | 図形の計量（三平方/相似で長さ・体積・角・面積）／関数の式決定（2点から式）・変化の割合 | 図形／関数 |
| 4 | **作図** construction | 条件 → コンパス・定規で作図 | 「垂直二等分線をかけ」「60°を作図」 | 図形（中1） |
| 5 | **図・グラフ・表** graph_table | 関数/データのグラフ・表を読む/かく、**図形を"かく"系**(移動/投影図/回転体/見取図/展開図をかく・読む) | 「グラフをかけ」「傾きを読め」「箱ひげ図」「投影図をかけ」 | 関数／データ／図形(作図系) |
| 6 | **証明・説明** proof | 命題・図 → 筋道立てた記述（証明・理由説明） | 「△ABC≡△DEFを証明」「なぜ偶数か説明」 | 図形／数と式(数の性質) |
| 7 | **文章題** word_problem | **設定（大枠）＋小問構成**の総合問題。設定を読み解き**何をどう求めるかを自分で構成**する。小問の多くは求値/計算 | 方程式/関数の利用、確率、図形の総合大問、入試融合 | 全 |

## 2階層モデル（重要・ユーザー指摘）
問題形式は2階層で捉える。**文章題は原子的タイプと排他でなく、求値等を内包する複合フォーマット**。
- **原子的タイプ（単問で何を問うか）**: 知識／計算／求値／作図／図・グラフ・表／証明・説明。
- **複合フォーマット = 文章題**: 大枠（設定）＋小問列。小問は原子的タイプ（多くは**求値**、時に計算/証明）。
  - 例: 「立方体を頂点を結ぶ線で切り取る」（大枠）→ (1)断面積 (2)表面積 (3)体積を求めよ（各小問＝求値）。
  - 文章題の難しさ＝**大枠のモデル化・ゴール設定**。中身の小問は求値の連なり。
  - 難易度＝**誘導あり（小問が求値を導く・標準〜応用）↔ 誘導なし（ゴールも自分で構成・発展/論述）**。
  - 大枠は現実場面（ばね・水そう・速さ）でも数学的設定（立方体の切断・放物線と直線）でもよい。
- **単問の求値 vs 文章題**: 「体積を求めよ」と対象が指定＝求値。設定を読み解き複数小問を構成＝文章題。

### 判別の決定木（迷ったらこれ）
- 問いが用語・意味 → **知識**
- 式が既に与えられ処理するだけ（立式不要） → **計算**
- 図・点・数学的条件から立式して量/式を求める（場面なし） → **求値問題**
- コンパス定規の作図 → **作図**
- グラフ・表を読む/かくのが主 → **グラフ・表**
- 記述で証明・説明するのが主 → **証明・説明**
- 現実の場面文から立式（活用） → **文章題**

### 型の相互排他ポイント（重要）
- 計算 vs 求値: **立式の有無**（式が与えられる=計算／自分で立てる=求値）。**変化の割合・変域を求める=求値**（(yの増加量)/(xの増加量)を自分で立式）。単なる代入（式が与えられ数値を入れる）=計算。
- 求値 vs 文章題: **単問で対象が指定=求値／設定を読み解き小問を構成する総合問題=文章題**（2階層モデル参照）。文章題の小問は求値を内包する。
- 求値 vs グラフ・表: **答えの性質**（量/式を求める=求値／図表を読む・かく=グラフ・表）。関数はグラフから読んで式決定なら求値、グラフをかくのが目的ならグラフ・表。
- 計量的な図形問題は原則 **求値**（旧v1で calculation としていた図形レッスンは求値へ）。純粋な公式代入（式が与えられ数値を入れるだけ）だけは計算に残してよい。

### レビューで確定した追加規則（v3.1）
- **graph_table は "図・グラフ・表をかく/読むthat目的そのもの" に限定**。証明・求値の**解答過程で与えられた図を読む/指し示す**のは独立フォームでない（proof/find_value/knowledge に内包）。純平面幾何の証明・角求値レッスンに graph_table を付けない。
- **確率の数え上げ＝求値**（式が与えられず場合を自分で構成して立式）。calculation は「相対度数＝度数÷総度数」等、式が与えられた純処理に限定。
- **2階層の非重複**: 文章題（大枠＋小問）の小問である求値は、文章題フォームに内包させ**独立の find_value を二重計上しない**。単問の求値が別に実在するレッスンでのみ find_value を併記。
- **単問求値 vs 文章題**: word_problem は必ず「設定＋小問（複数段）」の2階層。単問（対象1つ指定）を word_problem にしない＝それは find_value。

## 難易度 = 段（各段は「構造的に別物」・数字の大小ではない）
バンド(基礎F/標準S/応用A/発展D)は目安。**実際の難易度は (単元×形式) ごとに、構造的に区別できる段だけを列挙**する。
段数は固定でない（1〜3段が普通・4段はまれ/ほぼ無い）。**段を分けるのは"数字の大小"でなく下記の構造的差分**（過去に難易度が数値ジッターに堕して機能しなかった反省）。

### 形式別 構造ラダー（何が段を分けるか）
- **知識**: ①定義・用語の想起 → ②意味の理解・判別・具体例への適用。（1〜2段）
- **計算**: ①基本形1手順 → ②複数手順・数の複雑化(分数/負/多項/かっこ) → ③工夫・複数公式・置き換え。（2段。工夫が要る単元のみ3段）
- **求値**: ①1定理・1〜2手順で直接 → ②多段・補助線・複数定理 → ③逆算・融合・非自明な補助線。（2〜3段）
- **作図**: ①基本作図1つ → ②正確な基本作図 → ③複数作図の組合せ・条件充足。（2〜3段）
- **図・グラフ・表**: ①読む → ②正確にかく・複数情報 → ③複数比較・条件から構成。（2〜3段）
- **証明・説明**: ①誘導あり・1定理で直接 → ②補助線・2段階 → ③誘導なし・方針を自分で構成。（2〜3段）
- **文章題**: ①誘導あり(小問が求値を導く) → ②誘導ゆるい・場合分け・複数立式 → ③誘導なし・ゴール構成・融合。（2〜3段）

### 段を決める規則（厳守）
- **各段は隣接段と構造的に区別できること**。区別できないなら段を作らない（数字を変えるだけの段は禁止）。
- **段を削る基準は「構造的に別物が存在しないか」＝教育的判断のみ**。「現システムが生成できない」は削除理由にしない（それはフェーズ②のギャップ）。
- 段数は多くの計算・知識セルで **2**、単純なセルは **1**、求値/文章題/証明/作図で **2〜3**。
- 文章題・証明・求値の上位段は「誘導なし＝自分で筋道/ゴールを構成」を含意。

## 各レッスンの成果物（1件ごと）
- `lesson_id`, `title`, `unit_flag`
- `forms`: 必要な形式（主要度順）。各 = { form(7型key), levels:[ {level:1, band:"基礎/標準/応用/発展", desc:"この段は構造的に何か(1行)"} ... ], rationale }。
  - **levels は構造的に区別できる段だけ**を列挙（1〜3個）。band はその段の位置づけ。
- `notes`: 特記。

## 各レッスンの成果物（1件ごと）
- `lesson_id`, `title`
- `unit_flag`: 単元名/粒度に問題があれば指摘。無ければ "ok"。
- `forms`: 必要な形式リスト（**主要度が高い順**）。各 = { form(上の7型のkey), bands(F/S/A/D レンジ), rationale(なぜこの単元にこの形式が要るか1行) }。
  - form の key は: knowledge / calculation / find_value / construction / graph_table / proof / word_problem
- `notes`: 特記（v1から型を変えた点・注意）。

## 原則
- 生徒が「この単元やりたい→何を問うか選ぶ」で自然に選べる型だけを載せる。不自然な型は載せない。
- **システムが生成できるかは不問**（フェーズ②で診断）。
- 領域の目安: 数と式=計算・知識・(証明:数の性質)・(文章題:利用)／関数=グラフ・表・計算・求値・知識・(文章題:利用)／図形=求値・知識・作図・証明・(グラフ:座標)／データ=グラフ・表・計算・知識・文章題(活用)。
