## 3. 棚の仕組み（触る前に読む）

### 場面を1つ足すときに触るのは棚の1ファイルだけ

```python
SceneSpec(
    id="admission",              # ★params に載る＝dup_key の軸になる
    vocab=(("one", "item_candidates", ("item", "counter")),),
    render={ROLES_TOTAL: _admission_total},   # 役割の型 → 書き手
    requires=(("入園料", "入館料"), ("大人",)),  # G-SC3 が当てる
    forbids=("会費",),
    limits={"price_domain": {"int_range": [300, 1200]}},  # 場面ごとの数の相場
    limits_from_vocab=None,      # 引かれた語から定義域を計算する場合だけ
    vocab_first=False,           # 語彙が数そのものを決めるなら True
)
```

`SceneSpec` は `scenes.py` の**ジェネリックな1つ**を全モジュールが共有する
（場面の**文**の型だけが module 固有＝型引数）。

### ★役割の型は「本文に出る量」だけでは決まらない

同じ量の組でも分けるべきものが3組あった。

| 組 | 分けた理由 |
|---|---|
| 比例と度数 Lv2/Lv3 | **問いが違う**（一方だけ見ぬく／両方立てて2つ答える） |
| 連立 `distance_time`/`time_split` | **文字に置くものが違う**（道のり／時間） |
| 文字の式 `distance_letter`/`unit_convert` | **単位が違う**（時速km／分速m→km） |

**「何を問うか」「何を文字に置くか」「どの単位で言うか」まで含めて決める。**
型を共有させると、片方が他方の問いや設定文を受け取る。

### ★`pick_scene` は候補が1つでも draw を1回消費する

消費の回数が棚の大きさで変わらないようにするため。だから**棚に場面を足すと、
その役割の型を使うセルの生成物は動く**（golden の再承認が要る）。
逆に、他の役割の型のセルは1文字も動かない。

### 棚を1つ足したら

`records/work/scene_shelves.py` の `_SHELVES` に**1行足すだけ**。
検査（G-SC1・G-SC3・層の検査）はそこから棚の在り処を引くので、検査側には何も足さない。
