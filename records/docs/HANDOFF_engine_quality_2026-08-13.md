## 3. 次の人がいちばん知るべきこと

### ★ 解説の途中の手に値が入らないのは、欠陥ではなく安全策

解説の4,160手のうち**1,594手（38%）は括弧の中に値も式も無い**。読むと指示の言い直しに
見えるので、欠陥だと思って直しにいきたくなる。**行かないこと。**

```
因数分解 x² + 9x + 20
  指示: たすと1次の係数、かけると定数になる2つの数を見つける
  括弧: 2つの数を見つける          ← 「4 と 5」ではない
  括弧:(最後の手) (x + 4)(x + 5)   ← 最後だけ本物
```

根拠は3つ:

1. `G-Q5t`（漏洩検査）の対象は `problem_text` と **`hints`**（`explanation` は除外）
2. **ヒント＝解説から最後の1手を削ったもの**
3. したがって途中の手に値を書くと、**その値がヒントに載って答えの先出しになる**

だから**27個の solver に「narration には数字を書かない」と明記されている**。
因数分解の「4 と 5」は答えそのものなので、書かないのが正しい。

**ただし判断が要る論点が残っている（未着手・意図的に触っていない）**:
一律に値を落としているので、**答えに直結しない中間値**（往復問題の片道の道のり等）まで
隠れている。緩めるなら「答えから逆算できない中間値だけ許す」形になるが、
**27 solver 分の漏洩防止に触る**ので、単独で動かさないこと。

### ★ 「走査が空でも読むと出る」は健在。ただし読む角度が尽きかけている

過去3回とも、走査が空になったあとにコーパスを読んで欠陥が出た（R-8〜R-11、S-1〜S-9）。
**ただし630セルは全部1回読まれ済み**（4回目で読み切った）。5回目は「まだ読んでいない
form」ではなく「**まだ走査していない面**」（解説・ヒント）を開けて0件だった。

次の角度の候補は §5 に書いた。

### ★ 前の引き継ぎ書の重要事項は全部生きている

`docs/HANDOFF_engine_quality_2026-08-10.md` の §4（次の人がいちばん知るべきこと）と
`scratchpad/corpus/FIXES.md` 冒頭の「直し方の原則」は、そのまま有効。要点だけ再掲:

```
⓪ 定義域ではなく「答えの大きさ」で測る（定義域は広いまま、答えの分母・分子・
   根号の中に上限を置いて、超えたら組み直す）
① 軸を増やす（場面・道具・記号）。数は小さいまま組み合わせを稼ぐ
② params に場面を記録する（無いと dup_key が話の違いを見落とす）
③ どうしても届かないときだけ dup_rate_max を理由つきで宣言する

定義域を広げて通すのはもうしない。狭めるのも最後の手。
上限を決めたら、その上限で組が何通り残るかを先に数える
（100 seed の distinct は N(1−(1−1/N)^100)。dup ≤ 0.20 には約250通り要る）
引いたあと、組み上がったものが場面として成り立つかを見る
（負の長さ・立方体の高さが1辺と違う・三角形にならない3辺は全部この見落とし）
```
