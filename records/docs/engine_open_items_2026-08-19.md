## 1. 入試対策に証明のセルが1つしかない（exam_l6 のみ）

**現状**: 入試対策 84 問のうち proof は 1 セル。公立高校入試では合同・相似の証明が
確実に出るので、「入試対策」という看板に対して不足している。

**なぜ今やらなかったか**: これは**生成の失敗ではなく単元定義の話**である。
台帳（`units.generated.yaml`）に exam の proof セルがそれしか無い。A5（中1の
一次関数）は台帳の example が数学的に中2の内容だったので直したが、こちらは
「間違っている」のではなく「足りない」で、性質が違う。台帳を書き足すかどうかは
出題設計の判断なので、一存で決めない。

**やるなら**: `units.generated.yaml` の exam_l1〜l7 に proof のレベルを足し、
family YAML を書いて、既存の proof エンジン（`geometry/deduce.py` の前向き推論器）に
入試向けの構成を渡す。証明エンジン自体は完成しているので、足すのは構成と台帳。

## 3. 走査に残る数と、その理由（**これは残件ではなく「正しい状態」**）

後から走査を回した人が「まだ直っていない」と誤解しないよう、実測値と理由を残す。

| 走査 | 実測 | 理由 |
|---|--:|---|
| 座標平面に軸名が無い | 3 | 「方眼上に三角形ABCがかかれている」＝**座標軸の無い方眼**。x・y を書くほうが誤り |
| 本文が名指しした点が図に無い | 11 | **すべて答えになる点**（「点Aをとれ」「交点Nの座標を求めよ」）。図に打つと答えを図が言う |
| 同一セル内で骨格が重なる | 4 | 台帳が宣言している軸の違い。答えも違う（`10m+5` と `6m+3`／命題の真偽が逆） |
| ヒントが解説の写し | 5 | 概念名に点名や分数が入っていて使えない回。手順の1行に戻している |
| 立体の図に長さが無い | 0 | — |

走査の書き方でつまずいた点も残す:
- **「かきなさい」の解答欄**（`stroke="#e3e6ea"` の方眼）は、与えている寸法が無いので
  図に書きようがない。走査から除く。
- **面積（cm²）は辺に沿って置ける量ではない**。長さ（`cm` で `²` が続かない）だけを見る。
- 座標平面かどうかは**方眼の罫**（`stroke="#bbbbbb" stroke-width="0.5"` が縦横3本以上）で
  判定する。「縦線と横線がある」だけだと箱ひげ図・ヒストグラムを拾う（202 対 78 でずれた）。

## 4. 「今後も修正を続ける」ための設計上の申し送り

今回の作業で、**直しやすさ／直しにくさ**がはっきり出た。次に触る人のために残す。

- **描き手に部品を足して宣言で組む**のが速い（`render_construction_svg` /
  `_edge_dimension_labels` / `plot_named_points` / `side_by_side_svg`）。
  recipe 側は「並び順で寸法を渡す」だけにしてある。
- **同じ規約が複数の場所に複製されていると必ず取りこぼす**。頂点名から `I` を外す作業で、
  4 か所（`_FIGURE_LETTERS` / `_FIGURE_NAME_SETS` / 3 つの `_ALPHABET`）に散っていた。
  1 か所直して作り直しても消えず、全セル走査で初めて 0 になった。
- **ゲートとヒント生成が別々の基準を持つと食い違う**。数える語の表を共有していなかった
  ために 232 小問でヒントが作れなかった。今は `quality_gates._COUNTER_EXPR_RE` を
  唯一の出典にしている。
- **図はゲートを通っても中身が正しいとは限らない**。今回も方眼の目もりで2回外し、
  式のラベルの重なりで4回直した。付けた図は PNG に起こして必ず見る。
