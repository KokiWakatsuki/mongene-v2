# 問題形式の厳密な分類と拡張計画（Implementation Plan）

ユーザーの決定に基づき、新しい問題形式の追加と、それに伴う難易度設計・コンポーネントの改修、および単元ごとの厳密な分類ルールを実装します。

## 1. 採用された新しい問題形式の定義

既存の3分類に、新たに「A: 図形・視覚情報読解問題」と「D: 知識・定義の確認問題」を追加し、合計5分類として厳密に定義し直します。

1. **`calculation`（計算問題）**
   - 定義: 既に立式されており、純粋な式処理・計算アルゴリズムの適用のみを行う。
2. **`word_problem`（文章題）**
   - 定義: 自然言語の文章から状況を読み取り、自ら「立式（モデル化）」を行って解く。
3. **`visual`（視覚読解問題）** ※新規 (A)
   - 定義: 文章ではなく、図形やグラフから視覚的に情報を抽出し、立式・計量を行う。
4. **`proof`（証明問題）**
   - 定義: 論理展開（根拠と結論の連鎖）の手順そのものを記述する。
5. **`knowledge`（知識問題）** ※新規 (D)
   - 定義: 「合同条件」「定義」「用語」などを直接問う。立式も計算も行わない。

---

## 2. 難易度設計（Raw Score モデル）の修正

最近設計された `docs/difficulty_adjustment/implementation_plan.md` の「③ 問題形式（Problem Form）」による Raw Score ボーナスを、5分類に合わせて再定義します。
認知負荷（立式プロセスや論理構築の有無）に応じてスコアを設定します。

*   **`knowledge`（知識）**: `-100` ポイント
    *   計算も立式も不要であり、単なる記憶の引き出しであるため最も易しい。
*   **`calculation`（計算）**: `+0` ポイント（基準）
    *   立式不要でアルゴリズム適用のみ。
*   **`visual`（視覚読解）**: `+200` ポイント
    *   視覚情報から条件を見つけ出して公式に当てはめる（立式する）負荷が加算される。
*   **`word_problem`（文章題）**: `+400` ポイント
    *   自然言語からの変数抽出・立式という高い認知負荷がかかる。
*   **`proof`（証明）**: `+800` ポイント
    *   ゼロから論理構成を記述するため最も難易度が高い。

## 3. 新規 Blueprint と Atom の作成

新しい問題形式を出力可能にするため、専用の部品（Atom）と構造設計書（Blueprint）を追加します。

### A. `knowledge`（知識問題）向け
*   **`DefinitionAtom` (Noun)**: 「合同条件」「各種立体の定義」「用語（絶対値など）」などの知識データを保持するコンポーネント。
*   **`AskDefinitionVerb` (Verb)**: DefinitionAtom を受け取り、「この用語の定義を問う」「条件の穴埋めを作る」などのバリデーションとステップ生成を行う。
*   **`KnowledgeBlueprint`**: これらを組み合わせて、シンプルな一問一答形式の中間表現データを生成する。

### B. `visual`（視覚読解問題）向け
*   **`VisualModelingBlueprint`**: 既存の図形系（Geometry）や関数系（Function）の Noun Atom を流用しますが、**「問題文のテキストには極力パラメータを出さず、VisualDSL（図やグラフ）の中に数値を埋め込む」**ことを強制する構造設計書です。これにより「図を見て立式する」形式を確定させます。

---

## 4. 単元ごとの問題形式の「厳密な」分類

すべての単元において、「どの形式を出題してよいか」を厳密にホワイトリスト化します。
`master_data/mapping.json`（または `curriculum_math.json`）の各 lesson 定義に `supported_problem_forms` フィールドを追加します。

**【分類の注意点・実例】**
*   **中1: 絶対値** → `[knowledge, calculation]`（文章題や証明は不可）
*   **中2: 連立方程式の利用** → `[word_problem]`（「利用」の単元は計算問題を出さない）
*   **中2: 三角形の合同条件** → `[knowledge, proof]`（ただの計算は出せない）
*   **中3: 三平方の定理の計量** → `[visual, word_problem]`（基本は図形が与えられる。純粋計算は平方根の単元で出す）

これにより、ユーザーから「中2の合同条件で計算問題を作って」とリクエストされても、システムが適切に拒否（または形式を自動修正）できるようになります。
