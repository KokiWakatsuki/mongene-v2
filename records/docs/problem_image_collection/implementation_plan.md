# 実際の問題画像 一括自動収集計画（Implementation Plan）

テストに必要な1134件の実際の問題画像（PNG）を、完全にシステム側で自動収集するための計画です。
先の技術検証（PoC）で確立した「Playwrightでの自動ブラウザ操作」と「PDFからの画像変換」の仕組みを拡張し、全自動バッチ処理を構築します。

## 1. 収集の全体フロー

手作業をなくし全自動化するため、以下の2段階で進めます。

### フェーズ1: URLの自動マッピング作成
*   `forms_research.csv` にある各レッスン（例：中1 数学 正負の数）のタイトルキーワードをもとに、PythonスクリプトでWeb検索（DuckDuckGo検索APIなど）を自動実行します。
*   各 `lesson_id` に対して、取得先となるプリントサイト（ちびむすドリル等）の対象URLを見つけ出し、設定ファイル（`reports/url_mapping.json`）として自動保存します。

### フェーズ2: 全自動収集バッチの実行
*   フェーズ1で作ったマッピングファイルと、進捗管理シート（`problem_collection_progress.csv`）を読み込みます。
*   まだ「未着手」の行に対して、先ほど成功した「Playwrightでのアクセス → PDFダウンロード → 高画質PNGへの変換」を繰り返し実行します。
*   途中でサイトにブロックされたり、対象のPDFがない場合はエラーをシートに記録して次に進む「耐障害設計」とします。

## 2. 実行時間とバックグラウンド処理

1134件の画像を処理するため、**実行には数時間単位の長時間がかかる**ことが予想されます。
そのため、スクリプトの実行開始後はバックグラウンドタスクとして流し放しにしておく形となります。

## User Review Required

> [!IMPORTANT]
> 1. **全自動化による精度**: 検索キーワードを用いたURLの自動割り当てを行うため、一部のレッスンでは意図しない単元のプリントが選ばれてしまう可能性（ノイズ）があります。これを許容し、まずは「量が集まること」を優先して全自動で進めてよろしいでしょうか？
> 2. **実行時間**: 数時間かかる処理になります。よろしければ、この計画承認後に私が収集スクリプトを作成し、バックグラウンドで処理を開始します。

## Verification Plan
1. マッピング自動生成スクリプト（`scripts/generate_url_mapping.py`）を作成し、数件で正常にURLが取得できるかテスト。
2. 本番用の一括収集スクリプト（`scripts/collect_all_problems.py`）を作成。
3. 数十件バッチでテスト実行後、問題がなければ全件実行を開始。
