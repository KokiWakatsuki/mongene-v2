## 1. 直したもの（機械で確認済み）

### 1-A. 解説に「実際にやった操作」を名指しできるようにした（構造）

実物との差の本体は、引き継ぎ書の3点のうち **③操作の名指し**だった。
できていなかった理由は**構造**にある:

- `Step.narration` は**ヒントにそのまま流れる**（`t1_template._build_hints`）
- ヒントは G-Q5t（漏洩）の検査対象 → narration に数字を書けない（鉄則⑦）
- 結果、「両辺に同じ数を**たすかひくかする**」のように、その問題で何をしたのかを
  言わない形しか書けなかった（`equation.py` に「narration は なぜ を言う」と
  **意図的な妥協として明記されていた**）

→ `Step.detail` を足した。**解説にしか出ない欄**（ヒントにも問題文にも流れない）
なので実際の値で名指しできる。解説の行は `detail or narration` で組む。

```
narration  左辺を x の項だけにするために、両辺に同じ数をたすかひくかする。（ヒント）
detail     左辺を x の項だけにするために、両辺から 5 をひく。            （解説）
```

構造で守っていること（`tests/unit/test_t1_render.py` に3件の検査を追加）:
- detail は hints に出ない
- detail はテンプレートに公開されない＝問題文から書けない
- detail を書いた手は narration が出ない（同じことを2回言わない）

### 1-E. 証明エンジン —— 数学として誤っていたもの（★重い）

全5件を実物で確認したうえで、**根を直した**（個別の文字列直しではない）。

#### ① 循環論法 g3_l44.proof.Lv2

```
①、②より、中点連結定理が成り立つので  BC ∥ MN  …③
③より、平行線の同位角は等しいので     ∠ABC ＝ ∠AMN  …④
④より、錯角が等しいので               BC ∥ MN        ← ③の言い直し
```

根が2つあった:

1. `parallel()` が**線分の端点の並びを正規化していなかった**（組の入れかえだけ）。
   `BC ∥ MN` と `CB ∥ MN` が別の Fact になり、同じ主張を2度導けた → 正規化した
   （`perp` も同じ穴があったので直した）
2. それでも `parallel` と `parallel_dir` が**同じ日本語に書かれる**ので、
   深い方が結論に選ばれていた → **結論の資格として「途中で書いた行の言い直しは
   結論にしない」を足した**（`naturalness._restates_something_already_written`）。
   Fact の同一性でなく `fact_text`（証明文に出る日本語）で見る＝種類が違っても捕まる

いまの出力（正しい2組の角の相似）:

```
①、②より、中点連結定理が成り立つので  BC ∥ MN  …③
③より、平行線の同位角は等しいので     ∠ACB ＝ ∠ANM  …④
③より、平行線の同位角は等しいので     ∠ABC ＝ ∠AMN  …⑤
④、⑤より、2組の角がそれぞれ等しいので  △ABC ∽ △AMN
```

#### ② 存在しない対頂角 g2_l45.proof.Lv3/Lv4

```
対頂角は等しいから　　∠BAD ＝ ∠CAE
```

D は辺AC上・E は辺AB上なので、∠BAD と ∠CAE は**どちらも ∠BAC ＝ 同じ角**。
対頂角ではない（正しくは「∠A は共通」）。

根: `collinear` は3点を**並べ替えて**持つので**どれが真ん中かを持っていない**。
対頂角が成り立つのは交点が2点の**間**にあるときだけなのに、それを見ずに当てていた。

→ `between`（ある点が2点の間にある）という事実を足した。真ん中がどれかを知っているのは
**作図の手順**（`Construction.collinear_order`）なので、座標を測らずそこから出す。
`use_vertical_angles` は `between` が両方そろって初めて当たる。

**出す場所は1か所にした**（`Construction.between_facts()`）。最初は各作図の関数で
個別に足したところ、`constructions_similarity._line` を足し忘れて g3_l41.proof.Lv3
（砂時計型）が生成できなくなった——足し忘れる余地を消すため `collinear_order` から
まとめて出す形にした。

#### ③ 使っていない根拠 g2_l43.proof.Lv2/Lv3

```
③、④より、三角形の内角の和は180°で、他の2組の角がそれぞれ等しいので  ∠BAC ＝ ∠ABC
```

③ ∠ABC＝∠ACB と ④ ∠BAC＝∠ACB からは**推移律**で出る。内角の和は使っていない。

根: **推移律の規則が無かった**ので、`use_third_angles`（2つの三角形で2組の角が
等しければ残りも等しい）が**同じ三角形の中で**代用されていた。

→ (a) `use_third_angles` に「同じ三角形の中では使わない」を足し、
(b) `use_equal_angle_transitive`「同じ角に等しい角どうしは等しい」を足した
（面積の `use_equal_area_transitive` が先に入っていたので同じ形）。

```
③、④より、同じ角に等しい角どうしは等しいので  ∠BAC ＝ ∠ABC
```

※ 途中で「正三角形の作図は CA＝CB も保証しているのだから仮定に足せばよい」と考えたが、
**これは誤り**。family YAML の【深さ】が「二等辺の重ね合わせで示す（深さ2）」と
決めており、3組目を仮定に入れると結論が一手で出て問題にならない（YAML 自身が
Lv3 について同じ理由を書いている）。**仕様を読んでから直すこと。**

#### ④ 示していない条件で結論していた g2_l48.proof.Lv2

```
⑤より、1組の対辺が平行でその長さが等しいので  四角形BMDN は平行四辺形である
```

引いているのは ⑤ BM＝DN（長さ）だけで、**平行が証明文に出ていなかった**。
規則自体は平行を前提に要求していたが、`parallel_dir` が「図の組み立てを表すだけの
事実」として証明文に書かれない扱いだったため、根拠の文が名指ししている条件が
見えていなかった。

→ `Rule.shows_structural_premises` を足し、根拠の文が前提を名指ししている規則
（「1組の対辺が**平行で**…」）では、その前提を必ず行にして番号を振るようにした。

```
仮定より　　BM ∥ ND　…④
…
④、⑥より、1組の対辺が平行でその長さが等しいので  四角形BMDN は平行四辺形である
```

#### ⑤ 証明することが無い問題

`∠BAC ＝ ∠BAN`（N は辺AC上＝同じ角）を結論にした問題が出ていた。
→ 結論の資格に「同じ角を別の点の名前で書いただけの等式は結論にしない」を足した
（`ray_classes` で見る。`Deduction` が `ray_classes` を持ち回るようにした）。

#### 検査（再発防止）

- `test_vertical_angles_need_a_real_crossing` — 交わっていない配置に対頂角を使わない
- `test_proof_never_states_the_same_claim_twice` — **全 proof セル**について、
  証明文に同じ主張の行が2度出ないことを固定（循環論法の一般形をふさぐ）

proof 51セル × seed1〜3 = **失敗0件**（生成できることを実測）。

メモリにある「質のゲートの構造的な矛盾」の**実測値**。点名を dup_key に入れたのは
「dup を下げるため」だったが、その結果**中身が同じ問題を別物として数えている**。

### ★全630セルで測った（`records/work/measure_dup_without_labels.py`）

「影響は数セルだろう」と見込んで全数を測ったところ、**まったく違った**。

```
測ったセル 630 個（seeds=100・閾値 0.2）
表層を外すと閾値を超えるセル: 108 個   ← 17%
```

上位は 0.9 台（`g2_l36.knowledge.Lv1` 0.09 → **0.97**、
`g2_l44.knowledge.Lv2` 0.00 → **0.96**、`g1_l12.word_problem.Lv2` 0.18 → **0.95**）。

**つまり、いまの dup_rate は「表層の入れ替え」で通っているセルが 108 個ある。**
知識・用語のセルは特にそうで、中身は1〜数通りしかなく、人名・品物・点名で
100 通りに見せている。

なお現行でも 0.8〜0.9 と出るセルがあるのは、`dup_rate_max` を宣言しているため
（25 family が宣言済み。メモリの「③狭さを宣言する」がすでに使われている）。

### 判断: **いまは dup_key を触らない**

理由は3つ。

1. **17% のセルに一斉に効く**。閾値を割った 108 セルを直すには、
   1セルずつ数値の軸を広げる（＝量産の作業そのもの）必要があり、
   このセッションの残りでは終わらない。中途半端に外すとゲートが赤のまま残る。
2. **知識・用語のセルは、中身の軸が原理的に少ない**（「項とは何か」の言い換えは
   そう何通りもない）。軸を広げるのでなく、`dup_rate_max` を実測値つきで
   宣言するのが正しい扱いになる可能性が高い——それは1セルずつの判断が要る。
3. **いま緑のものを赤にしない。** 測って数を出したので、次に着手するときは
   見積もれる。

### 次にやるときの手順

1. `measure_dup_without_labels.py` で対象セルを出す（この表）
2. **中身の軸が広げられるセル**（動点・相似・文章題）は `fit_domain.py` で
   広い箱を探す。exam_l3 系は 0.21〜0.24 なので、あと少し広げれば届く
3. **原理的に狭いセル**（knowledge の用語想起など）は `dup_rate_max` を
   実測値つきで宣言する
4. 全部片づいてから `dup_key` の表層除外を入れる（順序を逆にしない）

## 3-G. ★自分で入れた退行と、その教訓（2件）

### ① detail が narration を置きかえるので、目的が落ちる（3回踏んだ）

`Step.detail` は解説で narration を**置きかえる**。値だけを書くと目的が消える。

```
× まず、27 を 100 でわる。（0.27）
○ まず、注目していることがらの数 27 を、全体の数 100 でわって、相対度数を求める。
```

→ 走査「解説の指示文が計算式だけ」を新設（合成データで動作確認）。
　 全走したら**自分が見落としていた2件**（g1_l56・g1_l57）が出た。

### ② ★narration に数字を書いたら、coverage_scan が2セルを丸ごと落とした

「ゼロ」と「0」の表記ゆれを直すつもりで、`exam_linear_figure.py` の

```
x 軸上の点は y 座標がゼロなので、y にゼロを代入して…
```

を「0」に直した。**narration はヒントに流れる**ので、G-Q5t が
「解答由来の値 '0' が problem_text/hints に漏洩」として落とし、
`exam_l1.word_problem.Lv3/Lv4` が **generated=0/5** になった
（元がカタカナだったのは、この回避のためだった）。

**直し方**: narration はカタカナ（数字なし）に戻し、**具体の `0` は detail に置く**。
これで生徒が読む解説には「y に 0 を代入して」と出て、ヒントは数字なしのまま。

**教訓（手順）**: **narration を1文字でも変えたら、そのセルで `check_cell` を回す**
（G-Q5t を 120 seed 通す）。走査だけでは足りない——走査は文面を見るが、
ゲートは「答えとの衝突」を見ており、見ている面が違う。

なお「narration に数字を書かない」を機械の走査にできないかを測ったが、
**助数詞を除いても 48 種が残る**（`90°`・`1000m`・`1/3`・`1以上10未満`・`12%の食塩水`）。
どれも given 由来で G-Q5t を通っており、走査では正誤を分けられない。
**見張りは G-Q5t 自身**であって、文面の走査ではない。

## 3-H. ★検査自身が間違っていた（文字の重なりでは指示と結果を分けられない）

既存の走査「解説の括弧が指示の言い直し」は、括弧と指示文の**文字の重なりが 0.9 以上**
で判定していた。読んで見つけた実物を食わせて測ると:

| | 重なり |
|---|---|
| 直す前 `（動く点の位置を x で表す）` | 0.77 |
| 直したあと `（進んだ道のり = 4x）` | **0.82** |

**逆転している。** 「進んだ道のり」という語を両方が含むからで、
**重なりは「指示か結果か」の手がかりになっていない**。この検査が 38 問を素通りしていた。

分かれ目は**値や式を持っているか**だった。指示の語尾で終わり、数も記号も無い括弧は
「その手で得たもの」になっていない。`_restated_no_value` を新設し、
合成 5 ケース（選択肢の答えを除外する場合を含む）で動作を確認してから全走した。

**★教訓**: 「0件が出たら検査が動いているか確かめる」の裏返しで、
**読んで見つけた実物を検査に食わせて、挙がることを確かめる**。
私は最初「語尾に `表す` を足せば直る」と考えて足したが、それでは直らなかった
（合成テストで気づいた）。テストケース自体も1度作り損ねている（短い指示文で試して
落ちた——実物の文で測るべきだった）。

新設した検査が全走で**6件**を捕まえた（水そう・動点2種・座標平面3種）。すべて実在で、
`g3_l54.find_value.Lv3` は**3手すべての括弧が記号の言い換え**で式が1本も無かった。
