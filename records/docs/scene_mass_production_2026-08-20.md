## 2. ★式は「1ファイル」にならない（charter の見立てが外れたところ）

charter §3 は

> 役割の型が既存と同じなら、新しい式は既存の場面にそのまま乗る

としていた。**実際には新しい式は新しい役割の型を作る。**

```
ax + b(N − x) = T   合わせて N 個。代金の合計は T 円      roles = (rate, rate, total, amount)
ax − b(N − x) = D   合わせて N 個。A は B より D 円多い    roles = (rate, rate, total, gap)
```

「合わせて N 個」は同じでも、**合計を言う節が差を言う節に変わる**。場面文はその節を
含んでいるので、乗せたい場面の数だけ書き手が増える（1つあたり 12〜16行）。

式を1つ足すときに触ったファイル:

| ファイル | 何を |
|---|---|
| `recipes/word_problem_linear.py` | 式・関係の枝・式の軸の宣言・ゲート3つの宣言 |
| `recipes/scenes.py` | 新しい役割の型の書き手（乗せたい場面ごと） |
| `checkers/word_problem_linear.py` | `form` を `solve_scene` に渡す（1行） |
| `tests/unit/test_recipes.py` | `form` で式を選ぶ（2か所・**落ちたので書き直した**） |

checker とテストが変わるのは**正しい**（二重解きは式を独立に知っていなければならない）。
つまり式の追加コストは場面の追加コストと桁が違う。**式は設計、場面は入力**である。

### 新しい式には非退化条件が付いてくる

どちらも「引く順番で保証する／定義域は狭めない」形にした。

- `ax − b(N−x) = D` は **D > 0** が必要 ⟺ `x₀ > pb·N/(pa+pb)`。単価が離れると x₀ の
  範囲が空になるので、**高いほうを A に置いて** x₀ を引き直す
- `ax + b(x−d) = T` は **x₀ > d** が必要（B の個数が 0 以下になる）

## 3. ★新しい場面が engine の暗黙の前提を暴いた

場面を足すと、それまで「買い物」1つだけだったから見えていなかった前提が出た。

| 出たもの | 何が前提だったか | 直し方 |
|---|---|---|
| 「植物園の入園料は、大人1人**130円**」 | 数の相場が買い物のものに固定 | `SceneSpec.limits` で場面が定義域を上書き。**場面を先に引く**順序に変えた |
| 「動物園の入園料は、大人1人**90円**、子ども1人**120円**」 | 式は `price_a·x + …` なので **x は必ず price_a の側**。どちらを大人と呼ぶかを固定していた | 高いほうを大人と呼び、**問う相手を price_a に合わせる** |
| 「**美術館**の**入園料**」「遊覧船の**乗車券**」 | 施設名だけを差し替え、料金名を固定 | 施設と料金名を**対で**カタログに持たせた（品名と助数詞と同じ扱い） |
| 「大人2500円・中学生2000円」（差500円） | 2つの値を独立に引いていた | **(高い\|安い) を対で1回引く**（(品物,値段) を平らにして引くのと同じ手） |
| 「180円切手」「290円切手」 | 額面を機械的に選んでいた | 実在する額面だけに |

下の3つは **G-BT（逆翻訳）の読み手が見つけた**。どれも数としては解けるので、
値の突き合わせでは出ない。

## 4. 残した欠陥（作業3 の範囲外と判断した）

**買い物の場面で品物ごとの相場が効いていない。** 読み手の指摘:

```
1個50円のなし（実物は200〜400円台）
1個140円のもも（実物は200〜500円台）
1個70円のグレープフルーツ（実物は100〜200円台）
```

果物・パン・おにぎりが g1_l25 の共通 `price_domain`（40〜160円）を共有している。
engine には既に `品名|助数詞|下限|上限` で相場を持たせる仕組み（`scene_vocab.draw_priced_item`）
があるので直せるが、**語彙と数を1回で引く**形になり「場面を先に引いてから数を引く」
順序と噛み合わない。**場面ごとの相場（`limits`）と品物ごとの相場（`draw_priced_item`）を
1つの仕掛けに統合する**のが筋で、それは作業3 の判断の外に置く。

---

## 5. 判断

**場面は量産してよい。** 1ファイル・40行・既存の関係に2つ以上乗る・文型が増える・
dup が下がる・G-BT 0 がそろっている。作業5（文型が1つしかないセルを 98 → 30 以下）は
この手順の繰り返しで進められる。

**式は1つずつ設計として足す。** checker とテストが必ず動くので、量産の対象ではない。
式を足すときは「乗せたい場面をどれにするか」を先に決める（役割の型が増えるため）。

**場面を足すたびに G-BT を1回読む。** 今回、機械検査5つ（G-SC1/2/3/4/5）は全部通った
うえで、読み手が4件見つけた。charter §1 の段階4「新しい文型を初めて書いたときだけ、
人が1回読む」はそのとおりで、**読まずに量産することはできない**。
