## 1. なぜ直したか

作業0 の前は、型の数え方（`records/work/build_corpus.py`）が**語彙違いを別の型として
数えていた**。実測 g2_l16.word_problem.Lv2 は 49 型として問題集に載っていたが、
品名を伏せると文型は1つだった。

```
N個N円の＿とN個N円の＿…  りんごの個数を x 個、レモンの個数を y 個とする
N個N円の＿とN個N円の＿…  おにぎりの個数を x 個、グレープフルーツの個数を y 個とする
N個N円の＿とN個N円の＿…  みかんの個数を x 個、パンの個数を y 個とする
```

charter が「段階2に入らない」と決めた違いそのものである。**物差しが狂ったままでは、
場面を量産しても効果が数字に出ない**（増えていないものと混ざる）。

## 2. 決めたこと（3つに分ける）

| 段 | 中身 | 型として数えるか | 何で見分けるか |
|---|---|:--:|---|
| **文型** | 構成フラグ・型の軸・解く筋道（narration）の骨格・問題文の骨格 | **数える** | `build_corpus.type_key` |
| **語彙** | 品名・人名・場所・色・助数詞・場面文の言い回し | 数えない（何通り出たかは併記） | `build_corpus.vocab_of` |
| **数** | `params["numbers"]` と文中の数字 | 数えない（同上） | `build_corpus.number_key` |

### 語彙の見分け方＝**鍵の名前で選ばない**

★この走査は一度外している。「surface らしい鍵の名前」を並べて除く書き方では
`item_a`（語彙）や `line_cost`（係数の並び）を取りこぼし、100セルすべてが seed 数と
同じ 30 型になった（＝走査が動いていない）。だから**engine 自身の宣言に従う**:

1. `params["slots"]` の下の値すべて（recipe が「語彙」として作っている場所）
2. トップレベルの params のうち、**かな・漢字を含む文字列**で型の軸として宣言されて
   いないもの（`item_a`・`statement`・`answer_labels`）
3. **YAML が「中身」と宣言したカタログの値**（`*_candidates`、人名・品物・場所の
   `*_set`、および 4. で軸から外したもの）。`|` で詰めた値は割って入れる
4. `*_set` と宣言されていても、**その値が recipe で `slots` に入るもの**
   （`dice_scene_set` → `slots.framing`）。宣言が2か所で食い違うので、実物を正とする

`params["numbers"]` の下は語彙として伏せない。そこには構成の語が混ざる——
exam_l5.Lv3 は `numbers.target_quantity` に「和」「積」を入れている（さいころの和が
5になる確率と積が6になる確率は数え上げの筋道が違う＝別の文型）。
**潰すより多く数える側に倒す。**

### ★踏んだ罠1 — 「ASCII でない」で語彙を選ぶと式が消える

`×÷²−` や全角記号は ASCII ではないが語彙ではない。「ASCII でない文字を含む」で
選んだところ、`given_disp` の `1/6×8×(-3.5)` が**式まるごと伏せ字になり**、
g1_l6.calculation.Lv2 の3型が1型に潰れた（「取りこぼした型」に出て気づいた）。
**語彙はかな・漢字を含む語**である。

### ★踏んだ罠2 — 伏せ字を seed ごとに変えると、畳むはずの操作が型を割る

はじめは「その seed が引いた値」だけを伏せていた。すると**伏せ字が当たる場所が
seed ごとに変わって、型が増える**（畳む操作で型が増えたら、その操作が壊れている）:

| 何が起きたか | 実測 |
|---|---|
| `unit="回"` の seed だけ「上**回**る」の回が消えた | g1_l56.graph_table.Lv3 が 1 → 3 文型 |
| `unit="点"` が「**点**を打ち」に当たった | g1_l55.graph_table.Lv2 が 1 → 2 文型 |
| 同じ「個」が slots 由来では `〈slots.counter〉`、カタログ由来では `〈語彙〉` になった | g1_l12.word_problem.Lv1 が 1 → 2 文型 |

直し方は**セル共通の語彙集合を、全部の文に、1種類の札で当てる**。当たる場所が
seed に依らなくなる。熟語の一部を余分に消すことはあるが（「半〈語彙〉」
「上〈語彙〉る」）、**全部の seed で同じように消える**ので型の数は動かない。
札を役割ごとに分けないのも同じ理由——同じ語が seed によって別の役割に入る。

余分に消したせいで本物の文型が畳まれた場合は「取りこぼした型（期待 N / 出たのは M）」
として表に出る。**0件も過大な数も黙って出さない。**

### ★踏んだ罠3 — 語彙を伏せると「答えの種類を決めている値」まで消える

畳んだ9セルを読み直したら、**1セルは畳んではいけないもの**だった。
g3_l57.word_problem.Lv2（全数調査か標本調査か）は調査の場面16通りを `slots` に
入れており、場面文の形はどれも同じだが**答えが「全数調査」と「標本調査」に分かれる**。
`slots` は語彙という宣言に従うと 16 型が 1 型に潰れる。

**まず答えを鍵に入れてみて、それが誤りだと分かった。** 答えは引いた数の関数なので、
鍵に入れると**数が型として戻ってくる**:

```
型の合計 943 → 1650（178セルが水増し）
  g1_l13.calculation.Lv2   1 → 59   答えの文字式が数で変わる
  g1_l1.knowledge.Lv1      1 → 2    「正の数」「負の数」＝引いた数の符号で決まる
  g3_l51.proof.Lv3         5 → 276  答えが証明の本文まるごと
```

正しい使い方は、**答えを「その置き場所が語彙か構造か」の判定にだけ使う**こと
（`structural_paths`）。置き場所 P の値ごとに答えの骨格を集めて、

1. どの値も**2回以上観測されている**（1回ずつだと 2. が自動で成り立ち、
   品名40通りのセルが全部構造になる）
2. 同じ値なら答えの骨格がいつも同じ（＝答えが P の関数になっている）
3. 値によって骨格が変わる（骨格が2通り以上）

の3つがそろったとき、P は語彙ではなく構造とみなして伏せない。
単射までは求めない——場面16通りに対して答えは2通りである。

これで g3_l57 は 16 文型に戻り、g1_l13 などの水増しは出ない。

答えの骨格は**語の部分だけ**（数と算術記号は落とす）。数を `＃` に置き換えるだけでは、
同じ型の答えが引いた数で約せたり約せなかったりして別物になる
（`36π cm³` と `32π/3 cm³`）。`ProofAnswer` は本文まるごとなので判定にも使わない。

単位が ASCII の `cm` も語彙に足した。`回`（漢字）は伏せるのに `cm` は伏せなかったので、
答えの骨格が「〈語彙〉以上〈語彙〉未満」と「cm以上cm未満」に分かれていた。

### ★踏んだ罠4 — 助数詞は params に出てこない

`container_set: ["袋|玉|個", "箱|カード|枚"]` のように語彙を1トークンに詰めている軸が
あり、recipe は `slots` に「袋」「玉」しか載せない。「個／枚」が残ると、品物名だけが
違う問題が別の型になる。だから **YAML のカタログの値も `|` で割って語彙に入れる**。

## 4. 実装の場所（同じ判定を2か所に書かない）

```
records/work/build_corpus.py
  type_key(params, narration, axes, text, universe)   ← 文型の鍵（唯一の定義）
  mask_vocab(text, universe)                          ← 伏せ字（universe はセル共通）
  vocab_of(params, axes, filler_words)                ← 語彙の選び方
  structural_paths(rows, axes, universe)              ← 答えを決めている置き場所は語彙でない
  vocab_catalogs(catalogs, vocab_values)              ← 語彙だった軸を外す
  measure_cell(...)                                   ← 1セルを測る（本体と道具が共有）
```

★頂点名から `I` を外す作業で、同じ規約が4か所に散っていて1か所直しても消えなかった
（4→2→0）。型の数え方も同じ轍を踏みやすいので、判定は `type_key` の外に書かない。

## 6. 残件（畳んだが、engine 側に構造が無いだけのもの）

- **g1_l58.word_problem.Lv4**（調査の計画）は 8 → 1 文型に畳まれた。答えが
  「平均値を比べる／中央値を比べる／階級ごとに割合を比べる」と**教育的には違う**が、
  engine 側ではその8つが**カタログの文をそのまま答えに写しているだけ**で、
  構造の軸が1本も無い（答えの骨格も語彙として伏せられるので `structural_paths` にも
  かからない）。物差しの誤りではなく、**そのセルに軸が無い**ことの表れなので、
  直すなら recipe 側で軸を立てる（作業3以降の候補）
- **exam_l5.word_problem.Lv3** は場面8通りが 4 文型に畳まれた。残った4つは
  `numbers.target_quantity` の「和／積」の組み合わせ＝数え上げの筋道の違いで、正しい

## 7. これで何が変わるか

- 問題集（`records/work/corpus/INDEX.md`）に載る問題は**文型ごとに1問**になる。
  語彙違い・数違いは載らない（何通り出たかは見出しに併記される）
- 「型が N 個」と言うとき、N は**文型の数**を指す
- 場面を1つ足すと（新しい `scenario_kind`＝構成フラグが増えるので）文型が増える。
  **語彙を増やしても数字は動かない**——これが作業3・作業5 の合否判定になる
