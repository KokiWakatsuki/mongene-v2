## 2. 作業3（式と場面の切り分け）の現物

`engine_core/engine/packs/math/recipes/word_problem_linear.py` が典型で、
**式1つに場面1つが貼りついている**。

```
FORMULATION_BUILDERS（式）          場面
  formulate_price_count        ←→  _scene_price_count
  formulate_surplus_shortage   ←→  _scene_surplus_shortage
  formulate_round_trip         ←→  _scene_round_trip
  …8種                              …8種
```

品物名・値段・速さは**軸として増やしてある**が、場面の骨格は式に固定。
ここを切れば 8×N に増やせる。同じ構造が `word_problem_*.py` の各モジュールにある。

**★切るときに必ず守ること**（過去に踏んだ）:
- **checker は同じ `FORMULATION_BUILDERS` を通して立式し直している。**
  だから「日本語の場面と数式の意味が合っているか」はゲートが見ていない。
  場面を増やすなら**逆翻訳（G-BT）で日本語だけを読ませて確かめる**
  （`records/work/bt_*.py`）。文型を数え上げて代表1件、では足りない
  ——同じ文型の別 seed で場面がありえない値になる。
- **増やした軸は `params` に載せないと `dup_key` に効かない。**
  `dup_key` は `params` だけから作られる。載せ忘れると dup_rate が下がらない。
- **`params` の数値は全部問題文に出ていること**（テストが強制している）。

## 4. 検証のやり方（並列化済み・この順番で）

```bash
# セル単位（数秒）。小さい修正はこれで足りる
PYTHONPATH=engine_core .venv/bin/python records/work/check_cell.py g2_l25 find_value 2,3

# 7ゲート・630セル（19分）
PYTHONPATH=engine_core .venv/bin/python -m engine.eval --jobs 7

# golden 280 family の再承認（17分）★単独で走らせる
PYTHONPATH=engine_core .venv/bin/python records/work/approve_all.py --jobs 7

# 全テスト（11〜12分）
PYTHONPATH=engine_core .venv/bin/python -m pytest engine_core
```

最新の実測（2026-08-16）: eval **7ゲート全部 OK** / approve **280 family 失敗0** /
pytest **exit 0 全通過**。

★**小さい修正で eval 一式を回さない。** `check_cell` で影響セルを見て、最後に1回だけ全走。
★**測っている最中に別のコマンドを同じ機械で走らせない。** 最後の pytest の
15分39秒はそれで汚れた値（clean な比較値は 11分32秒）。
