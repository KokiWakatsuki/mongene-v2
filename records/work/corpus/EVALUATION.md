## D-2 ✅【難】中1の数が実際の教材より大きく、端数だらけ

正負の数の加減（3項）で、分数と小数を混ぜた結果、答えの分母が 14 / 20 / 30 / 40 になる。

```
(-6/7)+(-3.5)+(-2)   → -89/14
(-4/5)+(-0.375)+6    → 193/40
8/3-(-0.1)-(-6)      → 263/30
```

この単元の狙いは**符号の処理**なのに、通分の計算負荷が支配的になっている。
実物（FdData 中1 正負の数）で扱う数は `-5, -2.5, -1/2, +8.5℃, -6℃` と小さく素直で、
分母は 2 まで。分母14の答えを出す教材は見当たらない。

**60 seed ずつ実測した規模**（半分以上が使えない）:

| セル | 分母13以上 | 最大分母 |
|---|---|---|
| `g1_l3.calculation.Lv2` | 32/60（53%） | 90 |
| `g1_l4.calculation.Lv2` | 31/60（52%） | 90 |
| `g1_l5.calculation.Lv2` | **44/60（73%）** | **420** |

最悪の例: `7/9-(-1.2)+4/7-0.6 → 614/315`

原因は `frac_domain` が分母 2〜9 を**各分数ごとに独立に**引くこと
（`g1_l5.calculation.yaml` は `term_kinds: [frac, dec, frac, dec]`＝分数2つ＋小数2つ）。
分母 9 と 7 で最小公倍数 63、そこに小数の 10 と 5 が掛かって 315 になる。
直すなら、1問の中の分母を共通にするか、最小公倍数が小さく収まる集合から引く。

## D-12 ✅【難・最大の構造問題】数の定義域が広すぎて、教材にならない数が出る

| 最大の数 | セル数 |
|---|---|

| 21～50 | 89 |
| 51～99 | 58 |
| 100～999 | **93** |

（標本調査の「20000個作る」・有効数字の「9780」・循環小数の「0.898989…」は適切）。
**図形の長さ・多角形の角数・確率の分母・相似比**は、ほぼすべて非現実的。

### なぜこうなったか（構造）

これは事故ではなく、**ゲートの設計から必然的に出た**もの。

- `dup_rate ≤ 0.20` を通すには、1セルあたり約250通りの組み合わせが要る
- 組み合わせを増やす最も簡単な手は**定義域を広げること**
  （メモにも「狭い箱より広い箱／dupは箱の広さでしか下がらない」と残っている）
- **教材として自然な数の範囲を測るゲートは無い**

つまり「同じ問題を量産していないか」は測っているが、
「その問題が教材としてありうるか」は誰も測っていない。**前者を通すと後者が壊れる。**

### 直す向き

定義域を狭めるだけでは dup_rate が跳ねる。**軸を増やして広さを稼ぐ**しかない
（三平方の面積証明で型5×文字120×記号5×向き2＝6000 を作ったのと同じやり方）。
場面・題材・文字・記号を軸にすれば、数を小さく保ったまま組み合わせは増える。

- 確認 989問を機械走査（`scratchpad/scan_defects.py` と数の分布の測定）。
  上位セルは `peek` で個別に確認し、適切なもの（標本調査・有効数字）と分けた

## ★ 解説の途中の手に値が入らないのは、欠陥ではなく安全策

解説の4,160手のうち1,594手（38%）は、括弧の中に値も式も無い。読むと確かに
指示の言い直しに見える:

```
因数分解 x² + 9x + 20
  指示: たすと1次の係数、かけると定数になる2つの数を見つける
  括弧: 2つの数を見つける          ← 「4 と 5」ではない
  括弧:(最後の手) (x + 4)(x + 5)   ← 最後だけ本物
```

**これは意図的**。根拠は3つ:

1. `G-Q5t`（漏洩検査）の対象は `problem_text` と **`hints`**（`explanation` は除外）
2. **ヒント＝解説から最後の1手を削ったもの**

因数分解の「4 と 5」は答えそのものなので、書かないのが正しい。

**残る論点（判断が要る・未着手）**: 一律に値を落としているので、
**答えに直結しない中間値**（往復の問題の片道の道のりなど）まで隠れている。
緩めるなら「答えから逆算できない中間値だけ許す」形になるが、27 solver 分の
漏洩防止に触るので、単独では動かさないこと。
