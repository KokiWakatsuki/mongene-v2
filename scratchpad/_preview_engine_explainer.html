出した問題が正しいことを、機械が確かめられる形にしておきたいからです。文と答えをまとめてAIに書かせると、その確かめができません。確かめ方は 05、AIをどこでなら使えるかは 07 で扱います。

04図はどこから来るのか

図も同じです。絵を用意して選んでいるのではなく、問題文の数から座標を計算して線を引いています。

図の種類と、もう1つの検査

形式ごとに違います。作図（定規とコンパスの線）、グラフ、投影図、箱ひげ図、度数分布表。どれも答えを先に決めて、そこから座標を出します。答えそのものを図に描いてしまわないことも検査しています。作図の問題で、答えの線を最初から引いておくわけにいかないからです。

05答えが合っているかの確かめ方

作ったときの計算をもう一度なぞっても、確かめたことになりません。そこで、問題文に出ている数だけを渡して、別に解かせます。

渡すのは名札のついた数だけ。答えも、問題文の日本語も渡しません。式の型は人が書いてあるので、確かめる側はそこに数を入れて解くだけです。日本語の解釈はどこにも入っていません。

受け取るものと、式の組み方を見る 
// 場面の種類と、問題文に出ている数
kind    = "price_count"
price_a = 130    // 「1個130円のなし」の130
price_b = 110    // 「1個110円のぶどう」の110
total   = 10     // 「合わせて10個」の10
cost    = 1200   // 「合計は1200円」の1200

場面の種類ごとに、式の型が用意してあります。price_count ならこれです。

def formulate_price_count(price_a, price_b, total, cost):
    return f"{price_a}*x + {price_b}*({total} - x) = {cost}"

→  "130*x + 110*(10 - x) = 1200"

人が書いた2行です。数を決まった位置に置くだけで、式そのものは考えていません。できた式は sympy という数式処理ライブラリが解きます。中学生が移項してやることを、記号のまま機械がやります。

作ったときは 130×5 + 110×5 と掛けて足しただけで、方程式は解いていません。確かめる側は印刷された 1200 から解いて 5 を出します。向きが逆なので、逆算を間違えていればここでずれます。

守れるのは、印刷された問題文と答えが食い違わないこと。守れないのは、「130 は単価」という日本語との対応づけです。

それぞれ、なぜそうなるのか

守れること。問題文に出ている数だけから解き直した答えと、作ったときの答えを突き合わせています。ずれていたら捨てます。答えを差し替えて出すことはしません。逆算を計算間違いした問題は、生徒に届く前に消えます。

守れないこと。「130 は単価、10 は個数」が合っているのは、問題文を書いた人と式を組む関数を書いた人が同じだったからです。機械が確かめたわけではありません。07 でこの話に戻ります。

この確認のほかに10種類の検査があります。答えが問題文に混ざっていないか、図に答えが描かれていないか、など。1つでも落ちた問題は捨てます。直しません。

07骨組みをAIに書かせられるか

まだ実装していません。設計だけあります。

話と式が1つの関数に一緒に書いてあるので、話だけ差し替えることができません。

いま
果物を買う話 ＝ a·x + b(k−x) = c
話と式がくっついている。話を1つ増やすたびに、式も書き直す。
→
切り離したあと
果物を買う話／バス代を払う話／切手を買う話
どれも同じ a·x + b(k−x) = c。式は人が管理したまま、話だけ増やせる。

話を書くのは AI が得意です。ただ、そのまま書かせるとこうなります。

横が縦より6cm短い長方形がある。その面積は 55cm² である。
縦の長さを x cm とする。縦の長さを求めよ。
式  x(x + 6) = 55 → 5cm
正しくは 11cm。日本語に従えば x(x − 6) = 55 で、縦が11cm・横が5cm。

「長い」を「短い」に書き換えただけです。それでも、すべての検査を通り抜けます。

なぜ検査に引っかからないのか

もとの文は「横が縦より6cm長い」で、そのときは 5cm が正解でした。「短い」にすると縦と横が入れ替わり、答えは 11cm になります。ところが式を組む関数が受け取るのは「6」という数だけで、長いのか短いのかを知りません。だから 5cm のまま出ます。

6 も 55 も本文にあり、式は解けて 5 になり、逆算した答えとも一致します。だから 05 の突き合わせも、ほかの10種類の検査も通ります。人が文と式を同時に書いていたあいだは起きなかった種類の間違いです。

足す予定の検査

1AIが書いた問題文を、別のAIに渡す。
2答えも式も見せずに「これを読んで方程式を立てて」とだけ頼む。
3返ってきた式が、人が管理している式と同じなら採用。違えば捨てる。

日本語から式を立て直させるので、「短い」と「長い」の取り違えはここで落ちます。この検査はオフラインで1回だけ回し、通った文型を焼き込みます。生徒に配るときは、これまでどおりAIは動きません。

着手順は決めてあります。①話と式の切り離し ②この検査の実装 ③AIで増産（docs/llm_template_expansion.md）。いまは①の前です。
